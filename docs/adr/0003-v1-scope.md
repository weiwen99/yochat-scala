# v1 范围 S1：两端各一台设备的加好友与单聊

**状态**: accepted (2026-11-20)

## 背景

旧实现把一句话需求「加好友，单聊」细化成 93 条需求、144 个 Quint 模型、205 个任务、约 25 万行代码，最后仍停在加好友与单聊。复盘的第一条建议是把自用场景砍到两台设备、在线单聊、消息落盘、重启不丢、断网重连。

用户的原则：只实现产品本身合理、可行的功能；不为发布级需求做自用工具。

## 决策

v1 是 **S1**：

- 一个用户 + 一个联系人，每个用户各一台设备；
- 通过邀请与应答加好友；
- 单聊；
- 先落盘再发送；
- 重启不丢消息；
- 断网后重连并继续；
- 本地密钥与数据库有最低限度的解锁保护；具体形态（系统钥匙串或口令）由 spike 决定，不做多用户切换。

## 非目标（v1）

- 多设备同步、新设备历史同步、设备吊销传播；
- 群聊、文件传输；
- 恢复短语、四设备迁移接管；
- 陌生人准入预算、公开隐私告知页；
- WCAG 2.2 AA 完整审计、十万条首屏 500ms；
- 完全 p2p / NAT 打洞（v1 是 relay-only，见 ADR-0002）；
- 发布级安装包矩阵与自动更新。

## 后续

- S2（自用多设备）：同一用户 2 台设备、新设备只读加入后消息、吊销；仍无群聊/文件。
- S3（发布级 MVP）：从旧 93 条需求中重新论证的子集。
- S2/S3 各自立计划，不塞进 0001。

## 取舍判据

**删功能，不删 S1 安全不变量。** 功能域可以按「删掉之后明天仍然能发一条消息」来砍；安全与生命周期不变量不接受这条判据。

S1 不可删清单（缺一条就不是 S1）：

- 应用锁是安全边界；锁定递增代数，旧代数的在途结果不落地（B9Y4E73VMQ8RS99X）。
- 空闲超时自动锁定，走同一条锁定路径（YQW27DXZJSHAR0Z0）。
- 密钥材料不进日志与崩溃报告；诊断默认不记录正文、联系人名或公钥（865PCSHV46Q4X2XF、DVFN7QEAWP32QD9G）。
- 只做定向邀请；邀请/应答绑定双方渠道标签与权威账号，不符进待确认并标记（2276A5JCK1KGNS1A、YP7HYFDC5BSKK1BP）。
- 应答方发出应答即完成本方确认；发起方在第一条经认证操作后确认；过期+宽限后降级并提示重新交换（A1MZYZ7JV43G7EJ3）。
- 拒绝应答只删本地待确认项，不产生 Send/Notify（KWW858WDBR49C9KS）。
- 入站先按联系人与邀请匹配；无匹配/未授权不落盘、不回应用层响应；不与未建立关系的对端交换消息（HYREM42TB44CYAHF、RYGFPP529TDA9R6X、MXHYRG96W0VKB031）。
- 签名、去重、时间不可信、按作者顺序这些跨切面不变量不因「功能少」而删除。

新增功能仍必须回答：

1. 它服务 S1 的哪个验收场景？
2. 它需要新的表、协议状态或组件吗？
3. 它的测试与性能代价是多少？

答不上来就不进 v1。

## 已知约束

- v1 不保证跨作者最终全序：只保证同一作者顺序。`REQ_20261103_GBNVF8ZY42F1DZX4` 在 S2 实现；T1 标记为不等价，不静默忽略。

## 后果

- v1 的产品面很小，但它是真的 friend-to-friend：两个用户、两台设备、一条可恢复的消息路径。
- 旧产品文档中与本 ADR 冲突的部分，以本 ADR 为准；旧文档仍是后续版本的输入。
- 中继是 v1 的已知依赖；没有中继时，两台设备无法跨网通信。这是已知约束，不是待补的洞。

## 2026-11-22 补充

用户确认 S1 接受 relay-only，范围为「一个用户 + 一个联系人、各一台设备」，不因中继而扩大功能面。数据 ACK、缺口请求、有界发送窗口和 10,000 条性能门是 S1 的协议/交付约束，不是新功能；详见 ADR-0008 与 ADR-0004。
