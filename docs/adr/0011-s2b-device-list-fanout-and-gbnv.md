# S2-B：联系人可见设备列表、设备扇出与 GBNV

**状态**: accepted and implemented for B1/B2/B3 on `feat/plan-0012-b2-impl` (2026-11-26); S2-B parity sign-off pending

**前序**: ADR-0003（S1/S2 范围）、ADR-0004（测试与性能门）、ADR-0006（S1 加密）、ADR-0007（存储）、ADR-0008（ACK/窗口）、ADR-0010（S2-A 只读伴随设备）。本 ADR 只覆盖 S2-B；S2-A 的本地移除、JoinManifest 与设备同步路径保留。

## 背景

S2-A 只让 A2 通过 A1 同步加入后的展示副本。它明确留下两项未关闭：联系人可见的设备列表/签名吊销，以及跨设备最终全序（GBNV）。S2-B 关闭这两项，并让 B 直接向 A2 发送，而不是只让 A1 转发。

这是对端协议的改变，不是 S2-A 的增量 UI：设备列表进入关系同步，B 需要为 A2 建立只读接收路径，消息需要跨作者统一顺序，吊销需要在联系人侧生效。ADR-0008 规定 `DataAck` 的语义在 S2 多设备时必须把被确认的 device 加进语义，另写 ADR；本 ADR 遵守这条，不直接复用 S1 的 `(sessionId, seq)` 作为最终回执身份。

## 决策

### 1. 设备列表是签名的、可合并的操作集

- B1 中只有主设备持有用户私钥；设备列表是一份带严格递增版本的用户签名快照，包含全部当前/已吊销条目。条目另带设备自签名。
- 接收方只接受更高版本；同版本不同签名拒绝；**吊销一经出现即永久生效**，新快照缺少已知吊销条目时整份拒绝。没有多签发者合并，这是已知约束。
- 签名覆盖用途标签、用户公钥、版本、条目、签发时间；不把到达时间或设备自称时间当作胜者。
- 联系人只验证签名、用户归属和当前设备；不在主界面按设备拆分会话。设备列表展示在本机/联系人详情。
- 关系建立期间，成员只用邀请/应答携带的设备；收到完整列表后转入并集规则。列表中不含交换期间那台设备时，它立即移出并告警。
- 新设备默认只读加入后消息；S2-B 不把历史同步塞进设备列表。

### 2. 一个主设备 + 最多一个只读伴随设备，双向对称

- 每个用户最多一台可写主设备和一台只读伴随设备。A1/B1 是主设备，A2/B2 是伴随设备。
- 伴随设备没有用户私钥，不能邀请、应答、签发设备操作/吊销、写业务消息；它是**直接接收者**，不再只是 A1 的同步副本。
- A1/B1 各维护与对方主设备的 S1 会话；另外各自建立与对方伴随设备的只读设备会话。伴随设备只接收、验证、ACK，不发送业务数据。
- B 发给 A2 的路径不使用 A1 转发；A1 发出的消息仍可从 A1 的 device-sync 到 A2，也可由 B 的 fanout 到 A2 的重复副本去重。不得让 A2 成为第二作者。
- 伴随设备被吊销后，主设备停止向它发送；联系人按收到的吊销原件停止向它发送；本机既有数据保留。

### 3. 设备会话与回执

- 只读设备会话用设备密钥握手：双方 X25519 ephemeral，签名绑定用户、双方 device、列表版本与会话用途；授权依据是对方用户签名的设备列表 + 当前未吊销状态；不借用 S1 用户私钥签名。
- 每设备会话有独立的发送序号与回执；逻辑消息用 `(authorDevice, authorSeq)` 标识，同一逻辑消息在不同会话里的 wire 序号不同。
- `DataAck` 的最终语义加入被确认设备：`(conversation, authorDevice, authorSeq, recipientDevice)`。界面可以在任一有效设备确认后显示“已收到”，但发送方按原始目标设备分别保留待补发项，不能用一个设备的 ACK 替另一个设备结清。
- 设备列表变化时，发送方按当前列表重算目标；已吊销设备不再新发，既有历史不重写。
- 伴随设备不写回 peer wire；它只发设备级 ACK 和控制确认。

### 4. 签名吊销

- 吊销是独立用户签名原件：用户公钥、被吊销设备公钥、签发时间、签发后的列表版本。原件保留，转交不改签。
- 吊销随设备列表控制帧分发给全部联系人；联系人验签后按“本机收到吊销的时刻”拒绝该设备此后到达的消息，不按消息自称时间回删历史。既有历史保留并标记来源已吊销。
- 设备列表不省略吊销；旧快照不能复活设备。
- 主设备本地移除伴随设备时同时生成用户签名吊销并发送给联系人；不再只做本地停止同步。
- 用户公钥与安全码不因吊销改变；伴随设备丢失不要求重建关系。

### 5. GBNV：两作者 Lamport + 因果前驱

- S2-B 的写作者只有双方主设备（A1、B1）；伴随设备不写。跨作者最终全序只为这两个作者建立，不声称覆盖未来群聊或第三台写设备。
- 每条业务消息携带签名的 `lamport` 和一组因果前驱 `(authorDevice, authorSeq)`（至少包含发送时已见的对方最大序号；并发为空）。作者收到对方消息后递增自己的 Lamport。
- 统一展示键为 `(lamport, authorDevice, authorSeq)`；同一逻辑消息在各设备上使用同一个键。物理时间不参与排序；同作者顺序仍由 `authorSeq` 保证。
- 接收端等待因果前驱后再放行；S1 的按作者 gap 等待继续生效，跨作者前驱只增加等待边，不跳过。窗口有上限，超出触发通道重建/补发，不丢弃。
- 全序证据随消息签名，不引入第三方排序服务或全局时钟。并发消息的平局按设备公钥与序号确定；不声称真实发送时间先后。
- 伴随设备从主设备同步和对方主设备直投两路取得同一集合，按同一键排序；重复副本按逻辑键去重。

### 6. 迁移与兼容

- 当前 schema 3（S2-A）；本计划升到 4：新增 5 表、逻辑消息键、顺序元数据；保留 1→2、2→3。
- 迁移用已有 S2-A 数据的 v3 夹具：旧消息、设备、同步游标可读；旧 S2-A 继续工作；回退只走备份，不自动降级。
- 协议版本升级；S2-B 使用新的 `WireFrame` v2，旧 S1 parser 不解析 v2；设备操作带签名 `features`，双方都声明后才启用直投/GBNV。未声明时保留 S2-A 路径（A1 同步到 A2，B 不直投）；不伪造“已升级”。
- 不保证 S1/S2-A 客户端与 S2-B 客户端混合时享受新保证；这是部署约束，不是新协议层。S2-B 默认关闭，操作者打开后才启用。

## 备选与否决

| 方案 | 否决理由 |
| --- | --- |
| B 只发给 A1，A1 再转发 A2 | 这是 S2-A；不能满足“联系人可见、B 直接分发、A2 可直接收” |
| 让 A2 持有用户私钥 | 违反只读边界；丢失 A2 等于用户根失守 |
| 用到达时间/服务器时钟做 GBNV | 不可验证、可被重放/伪造；与产品规格的签名排序证据冲突 |
| 用完整签名快照覆盖设备列表 | 并发签发会分叉；旧快照会掩盖吊销 |
| 只按版本号取最大 | 两台持用户私钥设备并发签同一版本会分叉；吊销可能被覆盖 |
| 为 S2-B 新增第二套 relay/服务 | 复用现有 opaque relay kind；新增服务面没有对应需求 |

## 后果与已知约束

- S2-B 仍是单联系人、自用工具；不做群聊、文件、历史同步、用户私钥同步、恢复短语、移动端。
- 主设备离线时伴随设备不能新增消息；伴随设备不接管发送。
- 吊销只保证收到原件之后的本机行为；离线联系人可能继续向旧设备发送，直到收到吊销。既有历史不远程擦除。
- GBNV 只覆盖两个主设备作者的当前会话；不覆盖未来群聊或多写设备。
- B1 只支持一个用户私钥签发者；用户私钥同步/多签发者不在本 ADR，需另立 ADR 补操作合并。
- 设备列表/吊销原件会占用有界存储；超出上限的处理必须失败关闭并保留原件，不静默丢弃。
- 迁移失败保留旧库并失败关闭；没有自动降级。

## 模型冻结

未跑就是未跑，不写成 PASS。

## 取代关系

本 ADR 不取代 ADR-0003/0004/0006/0007/0008/0010；它只关闭 ADR-0010 明确留下的联系人可见设备列表、签名吊销与 GBNV。S2-A 的本地移除/JoinManifest/1k 同步仍是已有能力，不回退。
