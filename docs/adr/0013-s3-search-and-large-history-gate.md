# S3-C：本地历史搜索的存储取舍与「大量历史」门

**状态**: accepted (2026-11-27；owner 委派执行者决定，原话「请你自主完成整个 S3 的开发和交付工作，
不必等下来问我」)

**前序**: ADR-0007（本地存储与密钥）、ADR-0004（测试与性能门）、ADR-0012（S3-A 存储扩展）、
Plan 0015（S3 范围；裁决 4 选「有界解密扫描」，裁决 5 要求定义十万条的数据形状与阈值）

## 背景

`messages.body` 是应用层 AEAD 密封的（ADR-0007 §3），SQLite 只看到密文。旧实现的「全文搜索」
依赖明文索引，直接照搬等于放弃一半静态加密；全局 `LIKE` 又必须整表解密，历史一大就不可用。
设计记录给出三个选项：A 有界解密扫描、B 明文索引、C 不做搜索；裁决 4 选 A。

同时，「大量历史仍可用」不能继承旧项目的 10 万条数字：那份口径没有记录数据形状、硬件与测量方法
（裁决 5）。本 ADR 定义形状与阈值，并把它们变成自动门。

## 决策

### 1. 有界解密扫描，不新增明文

- 读取路径：按 `id`（INTEGER PRIMARY KEY，即 rowid）倒序 keyset 分页，每页 256 行：
  `WHERE id < ? ORDER BY id DESC LIMIT 256`。第一页不带游标。
- 每行用既有 `MessageRepository.decode` 解密正文（同一 AAD 校验），在内存做
  `toLowerCase(Locale.ROOT).contains(needle)` 子串匹配。大小写不敏感，不做分词。
- 上限：单次搜索最多扫描 5,000 行、最多返回 50 条命中；命中达到上限即停止。
- 返回值带 `scanned` 与 `truncated`：`truncated` 表示**结果不完整**（命中达到结果上限，或扫描
  达到扫描上限，且仍有未读行）；扫描读到表尾时即使最后一页刚好命中也不算截断。结果不完整时
  UI 必须说明「已扫描 N 条 / 只显示一部分」，不得呈现成「没有结果」；搜索失败另有错误态，
  同样不得呈现成「没有匹配」。
- 查询计划由 `MessageSearchSpec` 的 `EXPLAIN QUERY PLAN` 断言钉住：**两条生产语句**（首页
  `id <= MAX(id)` 的界与后续游标 `id < ?`）都必须是按 rowid 的 `SEARCH`，不得 `SCAN messages`、
  不得 `USE TEMP B-TREE`（该表带密文 BLOB；ADR-0007 §5 禁止全表扫 blob）。首条语句若省略界会
  退化成 `SCAN`，因此首页显式带 `MAX(id)` 上界。
- 搜索只返回调用方本来就可见的消息：服务端用与消息列表相同的 `ApiJson.visible` 过滤，
  缓冲中的乱序消息不会被搜出来。
- 片段（snippet）在内存里从解密正文截取，不落盘、不进日志。

### 2. 「大量历史」的数据形状与阈值

- **形状**：一个会话、100,000 条消息、正文 128 字节、m1。最新 5,000 条走正常加密写入
  （搜索能解密），更旧的 95,000 条直接插入（没有任何门会读它们，只用来把表撑大）。
  这个区分写进 `SearchBench` 的文档，避免把数字误读成「10 万条全部解密过」。
- **门 1 首屏**：`listRecentMessages(50)` 的 p95 ≤ 250 ms（20 次采样）。
  它证明首屏成本与历史总量无关：只读最新 50 行。
- **门 2 搜索**：最坏情况——唯一命中位于 5,000 行扫描的最旧一行——的 p95 ≤ 1,500 ms
  （10 次采样）。它证明搜索成本被扫描上限约束，而不是被总行数约束。
- **实测（2026-11-27，m1，`./mill store.searchbench`，唯一回执行）**：
  `first_p50_ms=9 first_p95_ms=11 search_p50_ms=24 search_p95_ms=50 append_ms=3480`。
  阈值是回归护栏（约 20–60 倍余量），不是目标值；实测数字随机器变，回执以当次输出为准，
  其它文档只引用这一行，不再各记一套。
- 超阈值时 `SearchBench` 以非零退出，`check.sh` 失败：不允许静默放宽。

### 3. UI 与 API

- `GET /api/search?q=<2..200 字>&limit=<1..50>`：未解锁返回 401；`q` 或 `limit` 越界返回 400
  （越界**不夹取**）；存储失败返回 `store-failed:<code>`，不折叠成空结果。
- UI 在会话列表顶部提供搜索框（≥2 字触发，200 ms 去抖），结果显示联系人、片段与时间；
  点结果切到对应会话并清空查询。截断时显示已扫描条数。
- 搜索是本机只读操作，不产生网络帧，也不改任何存储。

## 后果

- 历史再大，首屏与搜索的成本都有上界；代价是**很旧的命中可能被扫描上限漏掉**，UI 用
  `truncated` 如实说明。
- 搜索只在已解锁进程内解密正文，明文不新增落盘；ADR-0007 的静态加密边界不变。
- 没有分词/相关度：子串匹配对中文可用（无需分词），但英文只能整词片段匹配。
- 搜索结果不跨设备：只读设备（A2）不显示搜索框、也不提供 `/api/search` 会话运行时；A2 的搜索
  随其只读视图后续评估。

## 已知约束

1. 扫描上限意味着「更早的匹配」可能搜不到；这是设计取舍，不是 bug；UI 必须显示截断提示。
2. 大小写不敏感基于 `Locale.ROOT`；不做 Unicode 归一化（组合字符可能匹配不到分解形式）。
3. 不提供正则、通配符、字段过滤或排序选项。
4. 搜索不改变 ADR-0007 的已知泄漏（行数、时间戳、密文长度）；片段只在内存与已解锁的界面出现。
5. **不覆盖 UI 滚动帧与内存增长**：旧 `scale.e2e.ts` 的滚动卡顿与 RSS 两项不在本波；本 ADR 的
   两道门是 store 级（解密 + 查询），不是绘制级。滚动阈值留待需要时另立门。
6. **搜索与写路径串行**：搜索整个分页循环在一个事务内、占用唯一连接（ADR-0007 §5 单写者）。
   搜索期间入站/发送落盘的最长等待等于该次搜索耗时（阈值上界 1,500 ms）；UI 去抖 200 ms，
   但连续输入仍可能排队。
