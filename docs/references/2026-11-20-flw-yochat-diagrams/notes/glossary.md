# YoChat（有聊）术语表

> 阅读版整理，源文件是项目内的 `docs/glossary.md` 与 `docs/engineering/*`，并按主题补充了架构与验证术语。
> 每条给出中文名、英文名和一句话解释；最后一节专门列出最容易混淆的几组词。

## 1. 产品与身份

| 术语 | English | 含义 |
|---|---|---|
| YoChat（有聊） | YoChat | 产品名。服务端不持有用户数据的端到端加密好友间信使。 |
| 用户 | User | 一个人在产品中的存在，由**本机生成的一对用户密钥**表示，不注册、无账号目录。 |
| 用户私钥 | User Private Key | 定义用户身份的私钥，恢复短语是它的可书写形式。只放在用户指定的少数设备上；持有它才能加设备、签吊销、发邀请与应答。 |
| 用户公钥 | User Public Key | 用户的公开标识，用于指称这个人、验签、计算安全码。**不是网络地址**，单凭它连不上任何设备。 |
| 设备 | Device | 用户的一台机器。必有设备密钥对与本人用户公钥，能正常收发；是否另持用户私钥由用户决定。 |
| 设备公钥 | Device Public Key | 设备在 P2P 网络中的地址，作用类似 IP：可寻址、可查在线状态。通信对方与联系人都能看到。 |
| 设备列表 | Device List | 某用户全部设备条目的**有版本集合**，由用户私钥签名，随关系同步给联系人。消息寻址到用户，再分发到列表中的设备。 |
| 设备吊销 | Device Revocation | 由持有用户私钥的设备签发的声明，使某台设备的公钥不再被接受；用户公钥与安全码不变。 |
| 设备别名 | Device Name | 设备持有者给自己设备起的名字，随签名设备列表同步；联系人可见但不可改。 |
| 用户别名 | Display Name | 用户给自己起的、同步给全部联系人的公开名字；只有本人能改。 |
| 用户头像 | Avatar | 与用户别名一样公开、只有本人能改的图片，有体积上限。 |
| 恢复短语 | Recovery Phrase | 用户私钥的可书写形式（BIP39，24 词）。可恢复身份、加设备、吊销设备；默认取不到加入之前的历史。 |
| 应用锁 | App Lock | 进入已解锁状态所需的口令校验，保护本地数据访问；与“是否持有用户私钥”是两件事。 |
| 应用会话 | App Session | 从一次解锁到下一次锁定之间的时段。锁定是安全边界，不是界面切换。 |
| 常在线设备 | Always-On Device | 用户自己的、长期在线且解锁的完整设备，在其他设备离线时替本人收消息。它持有解密密钥，不是只转存密文的中转。 |
| 实例 | Instance | 同一台机器上并存的一个用户或一个设备实例；各有独立数据目录、数据库密钥与应用锁。 |
| 用户私钥同步 | User Key Sync | 把用户私钥从一台已持有它的设备传给本人另一台设备；必须由持有方发起并双端确认。 |
| 历史同步 | History Sync | 把已有聊天历史传给同一用户的另一台设备；必须在持有历史的设备上发起，可中断续传。 |

## 2. 关系与联系人

| 术语 | English | 含义 |
|---|---|---|
| 联系人 | Contact | 与本人建立双向关系的另一个用户。关系由两轮交换建立，双方各自确认。 |
| 邀请 | Invitation | 发起方生成的文本，由**用户私钥**签名；携带用户公钥、渠道身份、一台设备公钥、一次性公钥（即邀请标识）、有效期与可选备注。 |
| 邀请标识 | Invitation Id | 一份邀请的唯一标识，取值就是它的一次性公钥；公开出现在邀请中，也出现在应答密文之外，便于定位。 |
| 一次性公钥 | Ephemeral Public Key | 专为某份邀请生成的公钥，应答用它加密；对应私钥只留在签发设备，过期或作废后删除。 |
| 邀请应答 | Invitation Reply | 应答方生成的文本，用邀请的一次性公钥加密、用应答方**用户私钥**签名；携带应答方用户公钥、渠道身份、一台设备公钥与邀请摘要。 |
| 渠道身份 | Channel Identity | 一对“渠道标签 + 本方在该渠道上的权威账号”；本地私有，在本人设备间同步，只在选用时进入某份邀请或应答。 |
| 渠道绑定 | Channel Binding | 借双方已在用的另一个渠道，把 YoChat 用户公钥与对方在该渠道上的权威账号对应起来的人工确认过程；强度不超过该渠道，也不能替代安全码。 |
| 安全码 | Safety Number | 供双方人工比对的短值，存在中间人时双方看到相同值的概率有设计上界。只解决“首次取得对方公钥”的问题。 |
| 好友别名 | Contact Alias | 用户给联系人另起的、仅自己可见的短名字，用来代替对方自设的用户别名显示。 |
| 好友备注 | Contact Note | 用户为联系人写的长说明，私有、可改、在本人设备间同步。 |
| 联系人分组 | Contact Group | 用户的私有分组，一个联系人可属于多个分组；也是文件共享可见范围的单位。 |
| 拉黑 | Block | 停止双向通信、拒绝发送、不把其地址用于主动连接，且不产生任何应用层响应。 |
| 删除联系人 | Contact Removal | 删除关系并询问是否删除历史；关系变更在本人设备间同步，删除历史则只产生逐设备确认的删除指令。 |

## 3. 消息、排序与补齐

| 术语 | English | 含义 |
|---|---|---|
| 聊天会话 | Conversation | 与一个联系人之间、或与自己的全部消息构成的有序序列；也是消息唯一存在的地方。 |
| 与自己的聊天会话 | Self Conversation | 用户给自己发消息的会话，与其他会话使用同一套机制，并在本人设备间同步。 |
| 日志位置 | Log Position | 一次**操作**在某台设备某条只增日志上的位置，连续无空洞；缺失检测、乱序缓冲、重发与放行都按它。**不是消息身份**。 |
| 消息标识 | Message Id | 一条**消息**在（会话，作者设备）内的编号，随内容加密；呈现、去重、墓碑、删除指令与引用都按它，重加密不改变它。**不是传输坐标**。 |
| 应用游标 | Apply Cursor | 某个（会话，作者设备）对的下一个待处理日志位置。它是承诺：只有一条操作的全部持久化效果提交后，游标才越过它。 |
| 等待 | Waiting | 某条消息未到、其后消息暂不呈现的状态；由乱序造成，会在缺失消息到达后自行结束。 |
| 超时动作 | Timeout Action | 形式化模型里对“等够了”的显式建模：每处等待都对应可在任意时刻、任意多次触发的动作，不假设等待终会结束。 |
| 通道重建 | Channel Re-establishment | 无法解开对方消息时，由接收方发起、双方自动重建加密通道并重传未确认消息；不丢已落盘消息。 |
| 重发 | Resend | 把已发过的消息再送一次。接收方察觉缺失后主动请求；发送方长时间无送达确认时兜底发起。 |
| 送达状态 | Delivery State | 已发送消息的可见状态，至少区分“已写入本地”与“对方已收到”；粒度是对方**任一未吊销设备已落盘**，不表示人已看到。 |
| 未读 / 已查看 | Unread / Seen | 用户自己设备组内的阅读状态，用于未读计数与同步；**不向联系人发送已读回执**。 |
| 删除 | Message Deletion | 用户在本设备移除消息内容：保留标识与排序信息、覆盖内容与引用摘要；不是撤回，不要求对方删除。 |
| 删除指令 | Deletion Request | 一台设备把删除传播给本人其他设备时的提议；到达后进入待确认列表，需那台设备上的用户同意才执行。 |
| 墓碑 | Tombstone | 删除后保留的消息身份与排序痕迹，防止重同步/重传让已删消息复活，也避免会话永久等待。 |
| 引用回复 | Quoted Reply | 引用某条消息进行回复；被引用内容的摘要随回复一起传输并落盘，因此对方不持有原消息也能看到。 |
| 全文搜索 | Full-text Search | 对本设备全部会话历史做全文检索，结果标明归属会话；未解锁时不能执行。 |

## 4. 网络与隐私

| 术语 | English | 含义 |
|---|---|---|
| 中转 | Relay | 双方无法直连时代为转发字节的第三方。可见双方**设备端点标识**、连接/投递时间、字节数/帧数、本机网络地址、协议版本与设备认证签名；内容与用户层身份仍受端到端保护。 |
| 直接连接 | Direct Connection | 两台设备不经中转直接建立连接；少一个观察方，但对端可得知本机公网地址。 |
| 发现信息 | Discovery Record | 为让别人找到设备而发布的记录；只含中转入口，不发布设备自己的直接地址。 |
| 端点标识 | Endpoint Id | 设备在中转/发现层的地址性标识；可见不等于用户身份可读。 |
| 准入预算 | Admission Budget | 在握手、分配大缓冲与密码学处理**之前**的全局限额（并发、握手速率、任务数、内存），并为已建立联系人保留容量。 |
| 连通纪元 | Connectivity Epoch | 某对端从不可达转为可达所开启的一段时期；兜底重发、请求重发等预算按纪元重置，纪元切换本身也限速。 |
| 端到端加密 | E2EE | 只有会话参与方的当前未吊销设备能解密；中转看不到正文与解密材料。 |
| 前向保密 | Forward Secrecy | 长期密钥泄漏不应使过去的会话内容可解；代价是未使用的解密密钥窗口必须有界。 |
| 在线状态 | Presence | 持有某台设备公钥的人可以查询该设备是否在线；这是 P2P 寻址的固有性质，产品不提供隐藏开关。 |

## 5. 状态、存储与运行时

| 术语 | English | 含义 |
|---|---|---|
| 纯状态机 | Pure State Machine | 只做 `step(state, event) -> (state, effects)` 的领域逻辑；不读时钟、不取随机数、不做 IO。 |
| 事件 | Event | 执行器送给状态机的输入：外部到达数据、用户动作、定时器到期、可达性变化、效果完成/失败。 |
| 效果 | Effect | 状态机返回的待执行动作，分五类：对外发送、持久化、起定时器、取随机数、通知界面。 |
| 执行器 | Executor | 驱动状态机、持久化状态、执行效果并把结果作为新事件送回的中层；负责崩溃安全顺序。 |
| 状态与效果同事务 | Atomic State+Effects | 状态推进与待执行效果必须在同一个事务里落盘；效果提交后才执行，执行后再标记完成。 |
| 效果幂等 / 去重 | Idempotent Effects | 崩溃重放可能导致效果执行多次，因此每个效果必须幂等或可去重；定时器按稳定标识与尝试序号去重。 |
| 授权代数 | Authorization Generation | 每个待执行效果携带的授权版本；真正出站前重新检查联系人、拉黑、设备列表与删除事实。 |
| 候选 | Candidate | 一次状态推进中独占取得、修改、校验并提交的工作状态；失败不发布候选。 |
| 冻结帧 | Frozen Frame | 已完成编码/加密的不可变发送字节；重试与转发原样复用，不重新编码或签名。 |
| 快照 | Snapshot | 某类状态的完整表示；新设计要求避免以完整序列化/反序列化做内部复制，只在真实边界编码。 |
| 修订 | Revision | 状态版本，如业务 `commit_seq`、设备 `ProtocolRevision`；用于 CAS、缓存与并发提交检查。 |
| 缓存工作集 | Cache Working Set | 有显式内存预算与淘汰规则的活跃状态缓存；只缓存已可靠提交的最终对象，命中不替代当前授权检查。 |
| 存储适配 | Store | 包住 SQLCipher 句柄的持久化层；所有可失败查询区分“不存在”与“读失败”。 |
| 单写所有者 | Single Writer | 每个状态由一个操作独占取走、更新、提交并归还；共享设备协议另受同一身份写入所有权约束。 |

## 6. 文件（后续阶段）

| 术语 | English | 含义 |
|---|---|---|
| 发送文件 | File Send | 把本机文件投递到聊天会话，默认不复制源文件，带默认七天的有效期。 |
| 共享 | Share | 把文件或目录标记为指定范围联系人可下载；默认不过期、不进入会话、不复制源文件。 |
| 共享根 | Share Root | 一次共享对应的本地文件或目录；对方只能看到其下的相对路径。 |
| 内容指纹 | Content Digest | 按分块计算的内容校验值；用于逐块验证、多源并发下载与一致性检查。 |

## 7. 验证与工程

| 术语 | English | 含义 |
|---|---|---|
| Quint | Quint | 项目使用的状态机规约语言；用 Apalache/TLC 做有界模型检验。 |
| Apalache | Apalache | 符号式有界模型检查后端，适合大状态空间与不变量。 |
| TLC | TLC | 显式状态模型检查器，时序性质与公平性验证走它。 |
| Kani | Kani | Rust 有界模型检查工具，只用于解析、序号运算、令牌解码等纯函数。 |
| proptest | proptest | Rust 属性测试库；状态机用 `proptest-state-machine` 与参考模型对拍。 |
| ITF | ITF | 模型轨迹交换格式；把 Quint 轨迹喂给真实 Rust `step` 做逐状态对拍。 |
| Checks | — | 模型公开正向验证入口的统一后缀；在 `models/checks.json` 登记安全/时序义务。 |
| fastcheck | — | `just fastcheck`：短源码/工具回归、格式、UI 检查与构建、模型类型、文档验证。 |
| fullcheck | — | `just fullcheck`：当前平台适用的全部自动检查，含 ignored 测试、完整模型证明、macOS 离线/GUI、Linux Kani。 |
| tao | — | 文档与检查编排工具；检查常量和截止在 `tools/run_checks.py` 维护。 |
| e2e | End-to-End Test | `e2e/` 下的 WebdriverIO 桌面验收；含大量原生场景（通知、焦点、重启、压力）。 |
| vendor | Vendored Dependencies | 固定上游发布包 + `patches/` 有序补丁重建的依赖树；不直接维护源码。 |

## 9. 最容易混淆的几组词

| 不要混用 | 区别 |
|---|---|
| 用户公钥 vs **设备公钥** | 前者指称“人”，用于验签与安全码；后者指称“机器”，是网络地址，可查在线状态。 |
| 应用会话 vs **聊天会话** | 前者是一次解锁到锁定的时段；后者是一段消息序列。不要用不加限定的“会话”。 |
| 日志位置 vs **消息标识** vs **应用游标** | 日志位置是“操作”的传输坐标；消息标识是“消息”的产品身份；应用游标是某作者设备下一个待处理位置。三者语义不同，类型也必须不同。 |
| 等待 vs **通道重建** vs **重发** | 等待是乱序造成的暂时状态；重建是无法解密时的恢复动作；重发是把已发过的消息再送一次。 |
| 送达状态 vs **已读** | 产品只承诺“对方某台设备已落盘”，不承诺“人已看见”。 |
| 删除 vs **撤回** | 删除只作用于本人设备，不要求对方删除；撤回无法保证对方没看到，产品明确不做。 |
| 拉黑 vs **删除联系人** | 拉黑停止通信但不删记录；删除关系是关系变更，历史是否删除另问。拉黑后删除联系人仍保留拉黑记录。 |
| 共享 vs **发送文件** | 共享是长期可取的目录/文件，不进入会话、默认不过期；发送是一次投递，默认七天有效期。 |
| 用户别名 vs **好友别名** | 前者是对方自设、公开的名字；后者是本人私有、只在自己界面替代显示的名字。 |
| 恢复短语 vs **应用锁口令** | 恢复短语是用户私钥的可书写形式，能恢复身份；应用锁口令只保护本机数据的访问。忘记口令可用恢复短语打开既有数据。 |
