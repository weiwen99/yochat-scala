# 术语表（旧实现 → 重写）

> 完整版：旧项目 `docs/glossary.md`（411 行，术语 + 缩写）；flw 的阅读版在 `../2026-11-20-flw-yochat-diagrams/notes/glossary.md`。
> 本表只收读需求与设计时最容易混的词，并标出重写 S1 / S2 / S3 的对应关系。定义以旧规格为准；这里的一句话是阅读索引，不是规范。

## 1. 身份与设备

| 术语 | English | 一句话 | 易混 / 重写 |
| --- | --- | --- | --- |
| 用户 | User | 一个人，由本机生成的一对用户密钥表示；不注册、无账号目录。 | 不是「设备」；S1 一个用户只有一台设备。 |
| 用户公钥 | User Public Key | 指称一个人、验签、算安全码；不是网络地址。 | 单独持有它连不上任何机器。 |
| 用户私钥 | User Private Key | 定义用户的私钥；恢复短语是它的可写形式。 | 只在指定设备上持久保存；S1 单设备，S2 多设备。 |
| 设备 | Device | 用户的一台机器；必有自己的设备密钥对与本人用户公钥。 | 日常操作以人为单位，不以设备为单位。 |
| 设备公钥 | Device Public Key | 点对点网络中的地址；可寻址、可查在线状态、可尝试连接。 | 联系人能看到；中转也能看到设备端点。 |
| 设备条目 | Device Entry | 设备列表中的一条：设备公钥、别名、加入时间等，由设备自签名。 | 由用户签名的设备列表授权。 |
| 设备列表 | Device List | 用户当前全部设备条目的有版本集合，由用户私钥签名，随关系同步。 | S2；S1 用邀请里的单设备例外。 |
| 设备吊销 | Device Revocation | 持有用户私钥的设备签发的声明：某设备公钥不再被接受。 | 用户公钥与安全码不变；收到声明后才生效。 |
| 恢复短语 | Recovery Phrase | 用户私钥的可书写形式。 | S3；ADR-0003 把恢复列为 S1 非目标。 |
| 设备别名 | Device Name | 设备持有者设置、随设备列表同步的名字。 | 联系人不能改。 |
| 用户别名 | Display Name | 用户设置、同步给全部联系人的名字。 | 公开、可改、可能重名；S3。 |
| 好友别名 | Contact Alias | 用户给联系人另起的私有名字。 | 不发送给对方；S3。 |
| 常在线设备 | Always-on Device | 用户自己的、长期在线、可替其他离线设备收消息的设备。 | 持有可解密其可见范围的密钥；S2 可选，锁策略待裁决。 |
| 应用会话 | App Session | 一次解锁到下一次锁定之间的期间。 | 不是「聊天会话」；锁定是安全边界。 |
| 应用锁 | App Lock | 用口令/钥匙串把本地数据与当前会话锁住。 | 锁定立即使会话失效；S1。 |
| 实例 | Instance | 同一台机器上的一个用户/设备运行实例。 | 每实例独立数据库密钥与锁；S2。 |

## 2. 关系

| 术语 | English | 一句话 | 易混 / 重写 |
| --- | --- | --- | --- |
| 联系人 | Contact | 通过邀请与应答、双方各自确认后建立关系的人。 | 不是「好友」这种平台关系；没有中心服务。 |
| 邀请 | Invitation | 用户私钥签名的一段文本：用户公钥、渠道身份、一次性公钥、签发设备公钥、有效期等。 | 分定向/不定向；S1 只做定向。 |
| 定向邀请 | Directed Invitation | 额外携带被邀请方在渠道上的权威账号，供对方核对。 | S1。 |
| 不定向邀请 | Undirected Invitation | 不携带接收者标识，可被多人分别应答。 | S3；公开张贴要说明代价。 |
| 邀请应答 | Invitation Response | 应答方用户私钥签名、加密到邀请一次性公钥的回复。 | 只有发起方能打开；必须在签发邀请的那台设备上确认。 |
| 渠道身份 | Channel Identity | 渠道标签 + 用户在该渠道上的权威账号。 | 本地私有、可跨设备同步；S3 做复用。 |
| 安全码 | Safety Code | 双方可带外比对的短值，用来发现中间人。 | 由双方用户公钥导出；S1。 |
| 拉黑 | Block | 停止双向通信、不产生任何应用层响应。 | S3；被拉黑方可能从传输行为推断。 |
| 删除联系人 | Contact Removal | 删除关系，询问是否删除历史；拉黑记录保留。 | S3；逐设备确认。 |

## 3. 会话与消息

| 术语 | English | 一句话 | 易混 / 重写 |
| --- | --- | --- | --- |
| 聊天会话 | Conversation | 用户与一个联系人（或与自己）之间的全部消息序列。 | 不是「应用会话」。 |
| 与自己的聊天会话 | Self Conversation | 只含本人设备的会话，用来跨设备同步信息。 | S2；不是「没有对端的本地笔记」。 |
| 设备组 | Device Group | 一个聊天会话的成员集合：参与方全部未吊销设备的并集。 | 关系建立期间例外，只含交换的两台设备。 |
| 先落盘再发送 | Write-before-send | 消息先在本地持久化，再进入发送。 | S1 的核心承诺。 |
| 送达 | Delivered | 对方任一未吊销设备已收到；不等于已读。 | 状态只到「已接收」。 |
| 已查看 | Viewed | 用户实际看到且短暂稳定的消息身份集合；按集合合并。 | 不是「最高消息编号」；S2 跨设备同步。 |
| 等待 | Waiting | 某作者的消息未到、其后消息已到时，暂不呈现后续消息。 | 只指乱序；不是「暂不可得」。 |
| 暂不可得 | Temporarily Unavailable | 等待超时/设备未答复等导致的临时放行状态，可逆。 | 与「等待」不同；S3。 |
| 不再提供 | No Longer Available | 依据某一版设备列表，收齐各设备签名声明后的放行状态。 | 不是绝对终态；内容后来到达仍接受。 |
| 重发 | Resend | 重新发送已发过的消息；由接收方请求或发送方兜底触发。 | 不是「重试」；有范围上限。 |
| 通道重建 | Channel Rebuild | 接收方无法解密时，自动重建加密通道并重传未确认消息。 | 有频率上限；S1。 |
| 历史同步 | History Sync | 新设备在持有历史的设备上显式发起，取得加入之前的历史。 | S2；与「重发」不同路径。 |
| 引用回复 | Quote Reply | 回复时引用某条消息。 | S3。 |
| 全文搜索 | Full-text Search | 在本地历史中检索。 | S3；删除内容不出现。 |

## 4. 顺序、存储与恢复

| 术语 | English | 一句话 | 易混 / 重写 |
| --- | --- | --- | --- |
| 日志位置 | Log Position | 每台设备在每个会话的只增日志上的坐标，用于补齐。 | 不是消息身份；u32，按（设备，日志）各数各的。 |
| 消息标识 | Message ID | 发送方给出的产品层消息编号，用于呈现、去重、删除、引用。 | 不是日志位置；重建后位置变、标识不变。 |
| 应用游标 | Apply Cursor | 每个（会话，作者设备）对上下一个要处理的日志位置。 | 是承诺，不是位置；全部持久化效果提交后才越过。 |
| 已决 | Settled | 已应用 + 已放行 + 已删除。 | 不是「已应用」；验收里的连续区间用它。 |
| 放行 | Release | 对不可得/等待批准的位置推进游标，带原因且可逆。 | 不是「跳过」；不是「应用」。 |
| 墓碑 | Tombstone | 删除后保留消息标识、覆盖内容的存储标记。 | 按消息标识记，不按日志位置；防止同步复活。 |
| 入组基线 | Join Baseline | 提供方为每个请求方记录的「加入成员集合时」的位置。 | 按（提供方设备，请求方设备，会话）局部量；S2。 |
| 删除指令 | Delete Instruction | 本人设备之间传播的删除提议，收到设备确认后才执行。 | 不是远程擦除；S3。 |
| 去重 | Deduplication | 同一消息标识/同一操作重复到达只呈现/应用一次。 | S1。 |
| 崩溃安全顺序 | Crash-safe Order | 状态与效果同事务落盘 → 提交后执行效果 → 再标记完成。 | 效果必须幂等；S1。 |

## 5. 网络与隐私

| 术语 | English | 一句话 | 易混 / 重写 |
| --- | --- | --- | --- |
| 中转 | Relay | 直连失败时转发字节的第三方设施；内容端到端加密。 | 能看到设备端点、时间、字节/帧数、本机地址、协议版本、端点签名。 |
| 直接连接 | Direct Connection | 不经过中转的设备间连接。 | 少一个观察者，但向对端暴露本机地址。 |
| 发现信息 | Discovery Record | 可被第三方查询的「如何找到这台设备」的信息。 | 不发布本机直接地址；S1 relay-only 更容易。 |
| 陌生对端预算 | Stranger Admission Budget | 在握手/大缓冲/密码学处理前限制陌生来源的全局资源。 | S3；S1 只有一个联系人。 |
| 端点标识 | Endpoint ID | 中转用来投递的设备级标识，定位等同网络地址。 | 不是用户公钥；中转不知道设备属于谁。 |

## 7. 最容易混的八组

1. **用户 vs 设备**：日常操作以人为单位；寻址、在线状态、吊销以设备为单位。
2. **用户私钥 vs 设备私钥**：用户私钥定义身份，能签设备列表/邀请/吊销；设备私钥只证明这台设备。
3. **设备列表 vs 设备组**：设备列表是用户全部设备；设备组是一个会话的参与方设备并集。
4. **聊天会话 vs 应用会话**：前者是消息序列；后者是一次解锁到锁定。
5. **日志位置 vs 消息标识**：前者用于补齐，后者用于呈现/删除/引用；不能互相替代。
6. **等待 vs 暂不可得 vs 不再提供**：乱序 / 临时放行 / 依据设备列表的放行；三者都不是「对方沉默」。
7. **重发 vs 通道重建 vs 历史同步**：补最近缺失 / 换加密通道重传 / 显式搬历史；三条路径，三种边界。
8. **吊销 vs 远程擦除**：吊销只让收到声明的设备拒收此后消息；不删除已持有数据，也挡不住持用户私钥的设备。
