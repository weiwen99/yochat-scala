- 状态：implementation draft（2026-11-27）；S2-B 功能已合入 `c5b5b86`。
- 范围：只关闭 S2-B 的发布风险；不新增产品功能、不改 S1/S2-A 对端契约。
- 前序：Plan 0012、ADR-0011、ADR-0003/0004/0006/0007/0008/0010。

## 2. 收口项

1. **能力门**：设备列表只在本地有活跃伴随设备或已收到带 `s2b` 的列表时声明 `S2b`；新业务消息只有在对方列表已声明 `S2b` 时才使用 `DataPayload` v2 / order metadata。没有声明的旧 peer 继续收 v1 payload。
2. **混合版本 E2E**：S1-only 双方不声明能力，保持 v1；S2-B 双方声明后直投和 GBNV 才生效。
3. **性能余量**：缓存 peer 能力/目标/伴随会话，`s2bperf` 保持 <5s 并进入自动门。
4. **安全与回退**：复核 fanout envelope 授权、ACK 身份、列表能力缓存失效和 schema 备份；关闭能力声明回到 S2-A 路径。
5. **签字**：owner parity 签字是人工 gate；本计划记录实现证据，不替 owner 代签。

## 4. 已知约束

- 能力声明是用户列表级，不区分具体条目；S2-B 仍只支持一个只读伴随设备。
- 不把外部密码学审计伪装成本计划完成项。
- 不引入 S3 历史同步、用户私钥同步、群聊、文件或第三写设备。
