# Plan 0007 设计评审：重建后的未确认消息

**Round 1/3：不通过，不冻结 7A。** 正确的基础是保留消息行、按旧业务键重封，并在同一事务提交新棘轮。尚未成立的是：恢复时不会撤销已完成的切换，旧消息一定先于新消息通过发送门，以及 7B/7C 覆盖了它们声称覆盖的入口。0006 的 R2-1、R2-4、R2-5 都保持 OPEN。

## 已核对的边界与验收切点

- **ID 与 SQL。** 新发的 id 来自 `AppRuntime.messageIds`，SQLite 自增 id 来自 `last_insert_rowid()`；`AppEffectExecutor.mapStore` 丢弃 `AppendResult`。恢复时 `AppStateRestore.outgoingFromRecord:187` 恰用 `record.id` 作为本次运行时 id；数值可能相等，不是可依赖的映射。G1 的定位应为 `(conversation_id, oldSessionId, author_pub, device_pub, seq)`，单条原地 UPDATE，不按运行时 id、不删插。用运行时 id **不等于** row id 的普通发送和一条相邻对照行取证：旧键不再命中，新键下是同一行，`id/created_at/author/device/seq` 不变，对照行不动；新 wire 的 header 与新键一致，新 message key + 新 wire hash 的 AAD 可解出原正文。`UNIQUE(session_id, device_pub, seq)` 已存在，不要求新索引/表。
- **写序与效果。** D:46–56 的写序 `sessions → messages → meta` 与 `MessageRepository.append` 及 ADR-0007 §5 一致；开头读取 lock/high-water 不是先写 meta。使用同一 `ConnectionIO`，不嵌套调用已自行提交的 `Store.updateSession`；一次成功使新 session 的版本/高水位同时 +1，重封不另增应用 `nextSeq`，也不重建 binding marker。`AppRuntime.applyEvent:401–412` 已提供“提交后发布”；接线必须经过 `isDurable → AppEffectExecutor.executeEffect → feedPersisted`，最后一处当前只收 `PersistOutbound`。`RebindPending` 则由 `executeExternal` 消费，交还 `Application.step(RebindOutgoing)`。用提交前无 `SendWire`、成功后从 `Persisting` 入 `Queued`、写失败后无候选发布和无发送区分各条路；无需第二个执行器。
- **真实 SQLite/重启。** (1) cutover 已提交、首个 rebind 未提交：原行/原 wire/未推进的新棘轮仍在，解锁后先发现待迁项，不由首次 online pump 发旧 wire；(2) 多条中仅第一条已提交、尚无持久化成功反馈：重开只重封剩余旧键，第一条复用逐字节相同的新 wire，不重复推进 `ns`；(3) 新 wire 已发、DataAck 丢失：恢复 `Pending` **和** `Sent`，重发已存 wire，B 去重并以新 session 的累计 DataAck 确认，A 最终 `Delivered`。恢复使用整段聊天的 `maxOutbound+1`，不是 ratchet `n+1`（`AppStateRestore.scala:131–145`）。既有 `CrashSpec` 覆盖 append，不是这三项的回执。
- **#14 验收。** `S1E2E.scala:478–528` 目前连续注入三帧，A 服务第一次 `sendMessage` 在切换之后。关闭 R2-1 必须让 **A 服务在自动重建前**发送并消费序号 k，保留其同一持久行；B 对原正文只显示一次，A 该行获认证 ACK 后为 `Delivered`；再发 k+1 也按序送达。只看到 Active id 改变或只看到新正文，均不能签收。

## 范围及残余风险

- 7B 是最近一次运行态通知，不是历史、必达推送或 GUI 展示。后来的 `Waiting` 可以覆盖它；`onState` 先于 external `Notify`，现有状态广播也不是通知已可读的证明。锁定时区分受保护的 `/api/state` 与 `/api/session` 的 locked JSON。本轮不要求持久化通知或新 UI。
- 7C 的固定窗口不是任意滑动 60 秒：一次在 0 秒、两次在 59 秒、下一窗三次在 60 秒，符合固定窗但跨界可突发。`AppService.lock:106–114` 销毁 runtime，下一次 unlock 重建 `AppState`；即使**进程未重启**也会清空预算。若接受内存实现，应写明边界为一次 runtime 生命周期（含锁/解锁重置），不宣称跨重启、跨设备或不可绕开的配额。既有 per-session pending/cooldown/attempt 上限仍独立生效。
- 7D 可保持无新表、持久字段、wire kind、header 或用户配置；7B 确有新的 HTTP 字段，7C 确有两个内存字段。无须新 outbox、分布式配额或修改 Quint。永久离线/永久丢控制帧只能要求有界且可见的失败，不能保证送达。`S1E2E.select` 当前列 #1–#7、#9–#15；D:109 的“#1–#15 全绿”不能用这 14 项代签 #8，#8/两进程 10k 仍按 S:28 排除，不在此扩项。

本轮两轴均已覆盖完整设计和 live spec。论证上不接受“保留旧行即最终退休”“单一发起入口即全部重建有界”两项推论；ID 区分和写序有代码依据。格式量测不适用（只审读），无正文改写可做保真差分，无独立人工签收。本轮未运行构建、测试、E2E 或模型；上列均非通过回执。按计划最多三轮，修订冻结后再审，不以本记录关闭 #14。
