# 三层验证策略

<!-- tao:section decisions -->
## 设计决策

```{adr} 三层验证策略
:id: ADR_20260918_TZQJ2R31QB6GYXQ2
:status: proposed

<!-- tao:field context -->
**背景与备选：** 规格对正确性的要求集中在两类地方：一类是分布式时序问题（按序应用、去重、重发、
通道重建、组成员收敛、删除指令的逐设备确认），另一类是边界与解析（信封解码、序号
运算、令牌解析）。这两类问题需要的工具完全不同，而没有任何一种工具同时覆盖两者。

演绎验证工具（Verus、Creusot、Prusti）本项目不采用，但理由不是"不支持 async"——
核心恰恰被设计成不做输入输出的纯转移函数，异步部分全在外层，用它否定内层方案是
错的。真实理由是投入产出：这些工具要求把数据结构与写法限制在它们支持的子集内，
并为每个函数写规约与证明提示，而本项目最需要保证的是多方交错下的时序性质，那是
模型检验的领域而不是逐函数演绎的领域。

<!-- tao:field decision -->
**选择：** 分三层，各司其职：

- **协议层**用Quint建模，同一份模型由所声明的后端检验，后端选择依据见下表；覆盖按序应用、
  重发、成员变化的并发及邀请交换。**时间必须显式进入模型**：每一处等待都是可在任意时刻、任意多次
  触发的超时动作，且每一个都要有确定的效果——一个永远使能却什么也不做的动作等于
  没有建模。模型不得假定状态流转瞬时完成，也不得假定所有设备终会上线。四条建模
  规则的权威表述在[架构](../architecture.md)，本条只引用，不另行复述，以免两份
  副本逐渐分叉。规约不是孤立
  产物：用它的模拟器导出执行轨迹，写一个回放器把轨迹逐步喂给真实的纯状态机并比对
  可观察状态。模型与实现一旦分叉，测试直接变红。
- **实现层**用 proptest 与 proptest-state-machine，对纯状态机跑随机事件序列并与
  参考模型对拍，对存储层跑真实 SQLite 验证事务性质。
- **纯函数层**用 Kani 做有界证明，只挂在解析、序号运算、令牌解码这类无 IO 的函数上，
  放在独立的持续集成任务里，因为它需要特定的工具链版本。

**协议层的后端分工**（实测得出，不是偏好）：

| 情形 | 后端 | 理由 |
|---|---|---|
| 论域大、结构简单（布尔量、小整数） | Apalache | 符号式、有界；把「k 步内有无反例」交给 SMT，不逐个枚举状态 |
| 论域小、结构复杂（集合、映射、嵌套记录） | TLC | 显式状态；这类模型的状态空间往往很小，而符号编码要展开的组合很大 |
| 需要公平性前提的时序性质 | TLC | 只有它完整支持 `weakFair`／`strongFair`，能识别无限执行的反例形状 |

**分界是论域规模与结构复杂度，不是安全/活性二分。**集合、映射或嵌套记录即使论域小，
符号展开也可能昂贵；不能因后端不适合就删去表达缺口、并发或前驱所需的最小论域。

因此**后端由各模型自己声明**，而不是由一条全局规则推导。

同一配置声明由TLC检验安全性质且包含时序性质时，在一次验证中同时提供全部不变量和以逗号连接的全部时序性质；后者按合取解释，不能只挑一条。安全与时序原步数不同时取较大值，不缩小论域、公平性或任一性质的边界。符号式安全检查仍保留原后端，其时序检查另交给TLC。这样复用同一完整状态图并减少冷启动，而不是把类型检查、导出或轨迹采样计为验证；启用该合并须用真实正控及两种反控确认：时序成立但安全失败、安全成立但时序失败，均必须判失败。

整批性质验证使用独立的3600秒执行截止，不与应用协议期限或Quint模型步数混用。大型完整状态图加全清单启动开销可能超过旧的1800秒整批预算；到期只表示本次未完成，不能冒充反例或通过。确需分段复用时，必须逐项匹配配置、全部性质、原边界及完整输入指纹，未完成项从头验证；有端口、输出及进程所有权隔离并经实际冒烟后才可并行，不能共享默认Apalache服务。任何分段的实际反例、失败或缺少明确结论仍使整批不通过。

模型结果缓存仅保存明确成功的确定性配置，命中时保留原验证来源并区分“复用”与“本次执行”。
键覆盖实际模型输入、完整配置/性质/边界、运行器/覆盖校验器、锁文件、实际工具链及影响语义的环境和配置；
不能只用文件时间、提交名或模型主模块名。以保守失效换取正确性；输入执行前后变化、损坏或不完整回执、
失败、超时、缺判词及清理不明均不能发布成功。即使部分任务命中缓存，其他任务失败仍使整批失败。
`--no-cache`禁用读取和发布，`--jobs 1`可独立验证串行路径；冷暖耗时分别报告。
动态Rust、真实网络、GUI、压力和进程所有权检查不缓存测试结果；Cargo可复用自身校验的编译依赖，
CI缓存也不能替代本次执行。多后端进程按总CPU/内存预算分配TLC线程，真实时间或性能敏感阶段不与重型工作重叠。
整批截止包含清理与缓存发布；控制器在总预算内预留有界收尾时间，不能让外层截止先杀掉尚未核验回收的进程。
工具身份保留实际文件字节和稳定版本/配置；HotSpot随ASLR变化的`java.vm.compressedOopsMode`不是模型语义输入，
不作为版本差异，但完整原始Java探测日志仍保存。其他运行时设置不因此豁免失效检查。

**Apalache 不做公平性，这不是版本旧。**此前核对的 v0.62.2 的
`tla-pp/.../temporal/TableauEncoder.scala` 里，`strongFairness | weakFairness` 仍然是
`NotImplementedError`（旁边还有 `guarantees` 与时序量词两条同类未实现）。Quint 自己在检时序
性质时会警告 Apalache 的时序支持是实验性的并建议改用 TLC。

**这与「不引入 TLA+」不冲突**，两者说的不是一件事。那条反对的是**用两种语言各写一份模型**，
仍然成立；而 TLC 是检验器不是建模语言——模型只有 Quint 一份，由 `quint verify --backend tlc`
自动编译过去，不新增一行模型代码。当初写那条时隐含了「Quint 只有 Apalache 一个后端」这个
没写出来的假设，`--backend=tlc` 自 quint 0.31 起提供，该假设已不成立。

**活性性质必须做反向对照。**带公平性前提检出「无反例」之后，要把前提去掉再检一次并确认它
**被证伪**；否则无法区分「系统真的满足它」与「前提不可满足使蕴含式恒真」。这一条写进策略，
因为后者在报告里与前者长得一模一样。

**模型/实现对应的边界。** 固定截止前成功需要明确的及时服务窗口，弱公平只保证最终获得调度，不能推出赶在截止前成功。同步SQL工作预算使用单调时钟，与邀请/协议墙钟及双方独立观察时钟分开；PKARR微秒路由序号不是可信业务墙钟。有限队列/成员闭包的结束不外推为无限生产或无限新候选下终止；真实签名、AEAD、事务原子性和外部服务器保新若作为模型输入，须由对应Rust/真实服务回归承担。

轨迹共享只在独立生成双方完整`states`/`vars`/verdict相同时删除重复副本，性质及事件断言仍独立检查，后来分歧必须失败；不同事件次序/来源的见证不得为去重强行合一。覆盖别名必须登记承担义务的配置、理由与源码指纹；观测字段细化、整数集合表示优化或纯alpha重命名只有在对应转移/性质确未改变时才复用证明。类型检查、有限路径采样、SQL/UI共享投影及终态集合对照各有不同范围，不冒称整个Rust状态空间穷尽、完整网络调度等价或真实GUI通过。历史状态数、原始哈希和失败结论不因去重/改名改写。

工具链以项目锁定的Quint及其适配Apalache版本为整体，不按上游主干说明单独换后端/JDK。
验证成功须同时有成功退出和明确`[ok]`，任何`[violation]`或缺结论均失败；退出码0本身
不证明检查发生，空模型集合的骨架通过也不承担业务性质。TLC队列清空的穷尽结论只
覆盖该有限模型；步数内无反例、类型检查、轨迹抽样不能换写为穷尽证明。非预期死锁须
保留，不能用无条件驻留动作消掉；有意终态驻留仅在真实终态使能
（{need}`TASK_20260919_4VA6XYGKJWWM56D2`、{need}`TASK_20260919_WSG175RHG9NHXPD0`）。

TLC也通过Apalache做模型导出。默认服务端口及中间输出目录为共享资源，runner的锁只
保护经该runner的调用；手工并发仍会冲突，资源耗尽造成的无结论不能当模型反例。
反控须从独立状态推导所检性质，不能把“该变体应失败”直接写进赋值；计数器只为
有限状态探索而饱和时，要保留首次越限见证，避免把待测量本身消掉
（{need}`TASK_20260919_WSG175RHG9NHXPD0`）。

Kani的证明范围以各harness的符号输入与边界为准。现有分层解析证明不覆盖签名库或
serde的JSON解析；TLV任意字节证明只展开短输入，被签编码单射性只展开所声明的小段/
列表规模。完整令牌“解码成功则重编码逐字节相同”曾因嵌套`Vec`分配无法在预算内
证成，现由随机性质用例承担，不能称为证明；消息标识递增的有界证明也不包含
`u64::MAX`上的那一步（{need}`TASK_20260919_SEMPP73D13V55EJ7`）。

<!-- tao:field consequences -->
**影响与后果：** 收益：协议缺陷在写代码之前就能被发现；对拍使规约保持承重而不是装饰；实现层的
随机序列覆盖了人想不到的交错。

超时之所以必须建模，是因为本设计里有多处"等待某件事发生"：等缺失的消息、等送达
确认、等重建完成、等全部设备答复是否仍持有、等吊销声明传到某个联系人、等用户批准
一次超限重发。若模型默认这些等待终会结束，它证明的就是一个不存在的系统——而恰恰是
"有一台设备再也不开机"这种情形最容易把会话推进永久停滞。模型要检查的是三件事：
任意超时序列下安全性质仍然成立；每条活性性质都把公平性前提写成时序形状（例如
"最终稳定连通"而不是"持续在线"，也不是只保证无限次可连通的写法），并各有一条不依赖该前提的安全对偶；以及由超时
引发的重试、重建与广播次数有界。

有界性的口径、纪元切换限速及本机超时之外的准入/按对端配额，权威表述均在
[架构](../architecture.md#DOC_20260918_94F65AR6A6WAQ9QM--verification)，本决定不另复制规则。

代价：Quint 规约是一份需要随协议改动而维护的独立产物，回放器本身也要写与维护。
这份成本是这套方案唯一真实的负担，而它成立的前提是核心逻辑确实写成了不做 IO 的
纯转移函数。

明确不做：不把 TLA+ 作为**第二种建模语言**引入——它与 Quint 是同一套语义，两种语言各写
一份模型等于重复劳动（用 TLC 作为检验后端不属于此列，见上文后端分工）；不引入 stateright
作为关键路径依赖，它发版节奏为一年一版且实质由单人维护。

形式化结论不自动覆盖产品接线。存储失败被翻译成语义答案、异步结果写到错误目标，
须由可失败查询类型、真实SQL故障注入及界面目标/生命周期所有权共同防护；单个模型
没有表达这些输入时，不能借它的通过声称排除了这两类缺陷。
```
