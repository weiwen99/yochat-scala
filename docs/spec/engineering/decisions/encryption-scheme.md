# 消息采用逐消息棘轮方案

<!-- tao:section decisions -->
## 设计决策

```{adr} 消息采用逐消息棘轮方案
:id: ADR_20260918_4CHZZB92TMDYWFRT
:status: proposed

<!-- tao:field context -->
**背景与备选：** 原选型时p2panda-encryption 0.7.1提供两套方案；当前0.8.1继续沿用此边界。数据方案（data scheme）让组共用一把对称
密钥，成员移除时轮换，旧密钥留在网络中，因此后加入的成员可以读到加入之前的内容——
它面向知识库、维基一类应用。消息方案（message scheme）为每个成员维持一条消息棘轮，
每条消息一把密钥，解密后丢弃。

规格要求新设备默认只能读取加入之后的消息，要求被吊销设备读不到之后的消息，也
要求前向保密。数据方案的设计意图与第一条正好相反。

<!-- tao:field decision -->
**选择：** 消息内容采用消息方案。解密棘轮的两个容忍参数须显式设定并写入配置：
`out_of_order_tolerance` 决定保留多少未使用的解密密钥以容忍乱序，
`maximum_forward_distance` 决定能跳过多少条。库的默认值是 100 与 1000。

本项目当前显式配置为16与32，明显小于库默认值；另有重发与通道重建兜底，不需要靠宽窗口硬扛，窗口越小，未使用密钥留存越少。该取值不声称已由真实网络乱序分布证明最优；后续调整须同时检验补齐、资源界限与前向保密的取舍（{need}`TASK_20260919_N0BEHW57ZGWS5B4A`、{need}`TASK_20260919_S8VPFC18M5CTXY2Z`）。

HPKE与p2panda的安全依赖升级不改变本项目选定的X25519、HKDF-SHA256和ChaCha20-Poly1305套件，
也不扩大上述棘轮窗口。版本升级须保留私料唯一所有权、认证后安装候选及失败原子回滚；
上游新高层Spaces API不自动成为本产品的协议路径（{need}`TASK_20261113_CZHJMR0J64PC611E`）。

<!-- tao:field consequences -->
**影响与后果：** 收益：前向保密、后加入者读不到旧消息、被移除者读不到新消息，三条都由方案本身给出。

代价：一次聊天会话的历史无法靠密钥"补发"给新设备——这正是规格把历史同步设计成
一次显式的、在持有历史的设备上发起的传输的原因，两者是配套的。

需要纠正一个常见误解：跳过一条消息并不会永久毁掉整条通道。解密棘轮会为跳过的代次
预生成并持久化密钥，在容忍窗口内仍可解开。真正不可逆的是超出窗口，此时正确的动作
是重建通道并重传，而不是跳过。系统仍然严格按序呈现与应用，理由是呈现顺序、窗口
有界、以及未用密钥削弱前向保密这三条，不是"跳过即毁灭"。
```
