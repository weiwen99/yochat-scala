# 普通联系人首次建组的自动接替与冲突收敛

<!-- tao:section decisions -->
## 设计决策

```{adr} 自动发现可用设备并保留冲突组的可恢复数据
:id: ADR_20261106_JW2F0N2YGZHXYGKC
:status: proposed
:links: CHG_20260918_NAHYZQ1MM6ZYT4S1

<!-- tao:field context -->
**背景与备选:** 用户2026-11-06明确要求：首次初始化设备离线或丢失时，其它在线合法设备自动接替，不要求等待原设备或手动重新交换。此前普通联系人没有产品首次建组入口，早期bootstrap模型只验证成功欢迎之后安装密码状态，未证明不同创建来源收敛。IndependentGroup::from_welcome拒绝不同来源，底层MessageGroup也拒绝已建组后直接接收第二份Create，不能靠去掉其中一条检查解决。

固定创建者不满足已确认体验；各设备按超时自行Create但只保留一个快照会分叉或丢失迟到消息；按当前可见名单选最小设备不能在名单传播滞后和分区时保证相同选择。所有已知设备或多数设备投票又会把离线设备引入首次开聊的等待前提。本方案保留分区期间的不同候选，网络恢复后以确定顺序收敛，不把超时当成原设备永不再出现的证明。

联系人确认及当前设备授权必须已有可恢复副本；永久丢失唯一本地确认而从未同步的事实不能被网络凭空补造。正常完成依赖双方各有合法在线设备、发现服务和通信最终可用、所需公开材料最终供应及公平维护。安全不依赖各端即时持有相同设备名单，永久断网下只保证单次尝试有界结束。

<!-- tao:field decision -->
**选择:** 按下列契约实现自动接替，以模型与真实密码回放作为产品接线前提；已完成的实施范围和剩余验证限制见[主计划](../../plans/2026-09/20260918-yochat-f2f-messenger.md#DOC_20260918_BFV4FCXTMM9MQRDD--verification)，不在此维护旧阶段状态。

1. **私有发现与首条操作。** 应答在既有签名/加密范围内加入随机联系人引导能力，双方仅通过本人私有同步将其复制给自己的合法设备。能力绑定双方用户、原交换和联系人代次；删除、拉黑、过期或代次变化使旧任务及结果失效。两侧以该能力派生不同的私有发现位置及加密密钥，发现记录只携带加密设备端点提示，不放用户公钥、设备名单、别名、正文或解密材料；提示只负责找入口，不能授权接收或提交业务。连接后首条引导声明须提供单设备、空别名的用户签名列表，以及该设备对本次声明/交换代次的持有证明。前者仍采用SignedDeviceList原有签名规则：持有用户私钥的设备在签入设备时，额外签一份最小列表并交给目标；目标日后可在没有用户私钥和完整对端名单时提供它。不得从完整列表删除其它条目后冒充仍有有效签名，也不把最小列表并入资料/改名投影；当前吊销、拉黑、关系代次及尝试所有权另行重查。能力仅承担定位、外层加密及完整性；实际网络端点与设备证明还须以目标发现接收公钥作HPKE封装。每台设备在签入时取得用户签名的接收证书，证书只含用户、设备承诺值、专用HPKE接收公钥与签名，不含真实设备端点、别名或其它设备。承诺值为按用途及用户隔离的设备公钥哈希，已知吊销可据此匹配证书；持有旧能力并不能从承诺值恢复未知高熵网络公钥，也没有其它设备的接收私钥；已独立知道候选设备公钥的人仍可匹配其归属，普通哈希不提供匿名或抗候选集合关联保证。接收私钥从本机设备私钥按用户及用途独立派生，证书可随本人同步复制，因此不依赖原交换设备或持有用户私钥的设备在线。应答方可维护此类不含真实端点的接收验证材料，私有设备入口与业务回应仍须等到验明发起方当前合法设备的首条引导声明后才发布；建联后才能发布接收验证材料会造成循环等待。双方原交换设备都离线时，其它已持有确认/能力副本的在线设备仍能相互发现，不能把已知完整对端名单或地址当成实现前提。发现报文须有大小、频率、并发和固定请求期限，撤销优先于旧声明，缺授权证明不得产生业务回应。

   **共享接收证书位置的尝试所有权。** 同一用户、联系人作用域及位置代次的接收证书共用一个PKARR位置；成功发布只确认该次写入，不能证明其它合法本人副本后来没有覆盖它。原设备在替代设备发布后写回并完成/停止时，旧固定尝试到期后的新nonce必须重新取得本轮发布确认，不能沿用同代次的旧确认而跳过发布；取消/重启同样隔离所有权。确认须同时属于当前代次、nonce和确切待完成请求，迟到旧回调不能授予新轮确认。失效的是共享位置的旧发布信用，不是仍有效的根签接收证书、有效缓存或单调时间戳。每个既有尝试内仍按原额度发布，不新增周期重发或重试预算，不延长固定六十秒尝试、十秒HTTP调用或原九十秒验收期限。条件消费进展明确依赖竞争写入有限且服务在该不变期限内提供公平成功窗口，不承诺任意持续last-writer竞争下的公平性；定向模型区分实际位置选择、接收者绑定提示投递与本机消费，旧确认保留为负例，而非把发布标志当作消费证明。该接线及验收责任归属 {need}`TASK_20261106_24PEVXETDE0NDVEJ`，不引入新的隐私协议。

   **帮助者轮转的实际容量与进展。** `openChat`是本地打开联系人会话的意图，不是远端授权；替代设备须先有该意图才发布本机提示，只有仍为opener才发Hello。双方同时打开时，较低root key保留本地nonce，较高一方验证后采用该nonce并降为responder；响应端`Completed`只表示签名Ack/Bundle offer已提交，不代表单方面安装聊天密钥。成功的本地send仅证明入队，不能当作远端已处理；每名已验签帮助者至多两次成功本地发送后交出固定目标，立即失败则立即释放。每秒一次Hello、固定六十秒attempt最多容纳六十名不同帮助者，第六十一名不挤掉已观察项；不能借用Iroh并发连接上限32作为选择器容量依据，也不承诺超过六十名在同一attempt内公平。单槽LWW可能永久隐藏某设备，类别轮转不保证所有提示都被看见。nonce替换须清除旧目标、节奏、预算和initiator姿态，迟到发送结果只能记入捕获的nonce；五类定位请求/发布还须同时核对精确request id。独立已认证证书与单调timestamp保留，不把重置调度误作撤销密码事实。

   此边界由`contact_discovery_driver.qnt`、`contact_helper_sweep.qnt`、`contact_bootstrap_cross_open.qnt`及`contact_discovery_lookup.qnt`分担；同步选择器不冒称HTTP worker/密码/SQL模型。条件进展依赖稳定授权、充足额度、SQL成功及固定期限内实际服务窗口，取消/重启只保证清理与迟到隔离；404允许本轮首次发布，不允许推进位置代次，传输错误仍按既有节奏重试。真实Iroh/PKARR路径与干净产品/分区验收的当前状态见[主计划](../../plans/2026-09/20260918-yochat-f2f-messenger.md#DOC_20260918_BFV4FCXTMM9MQRDD--verification)，不再由旧会话阶段表决定。

2. **候选身份与选择。** 候选标识绑定逻辑会话、持久逻辑代次、作者设备及随机作用域，受签名/密码绑定；顺序按逻辑代次、作者及候选标识的确定字节序，不使用接收时间或真实时钟排名。新的创建不回绕代次或复用原作者日志位置。已有可用组时先找当前持有者加入；没有可用持有者时，其它合法设备可建立更高候选。并发候选允许存在；更高元数据本身不替换活动密码状态，只有当前授权、来源原件和本次欢迎完整验证后才准备切换。
3. **原子切换与迟到内容。** 活动候选只单调前进，旧快照进入有界、可计量的接收保留区；旧组迟到原件仍按原作者签名及密码验证处理，不因切换丢弃正文。退役组不再产生新出站原件。准备、当前版本/作用域重查、密码材料、签名原件及可靠任务同事务提交；错误、取消及重启不提前切换。新的尝试取得新作用域和新固定期限，不把迟到结果当续期。
4. **身份、顺序及披露。** 用户消息身份、统一排序证书和原始受众独立于候选组；切换不重置消息标识、作者原生日志游标或回链。重封复用ProtectedContent及原受众秘密规则，不让新设备因合并候选读取加入前内容，历史仍走批准。旧快照/缓冲/任务的擦除和资源退还须与现有删除语义一致。资源不足时有界失败并保留可重试事实，不能偷偷删除仍需解码迟到消息的状态。
5. **有界发现记录与位置恢复。** 接收证书和提示分别使用按联系人作用域、方向、用途和位置代次派生的PKARR键；外层用独立派生的XChaCha20-Poly1305密钥，签名/加密密钥不混用。正文提示必须先经过目标HPKE，不能只用联系人能力加密后发布。查询与发布沿既有十秒HTTP总期限；证书外层217字节，最大提示外层649字节，单条TXT使用多段字符字符串，最大签名包1058字节，低于1104字节协议上限。已验签但正文坏的记录只提供可覆盖的路由序号，不能提供设备授权。路由序号不参与消息顺序。

   达到保留高序号的位置只表示该位置退役；验证当前代次的定位签名后，逐代前进，不跟随正文指定的任意跳转，也不因404前进或回到0。进度与单个旧位置维护游标持久化，每次只维护一个旧位置的签名退役标记，空间为常数；服务端移除旧标记后仍可重建，让新启动的读者追上当前位置。旧代次结果不能推进新代次，不回绕代次上限。该恢复的正常进展依赖耗尽前缀有限、攻击/故障最终停止、维护与读取有公平成功窗口；不承诺持续攻击下成功，也未测量很长耗尽前缀的恢复延迟。已知前缀的顺序扫描/维护成本随长度增长，但不能在一次调用中无界遍历。
6. **实际协议约束。** 新Create可出现在已提交全局游标处，准备和恢复的来源原件不能继续硬编码位置0。引导身份在签名原件和密码绑定中区分于逻辑会话，读取/恢复/补原件按同一身份选状态。旧组只读接收、跨来源冷接入、非零位置创建及原受众重封须先通过真实密码实验，再扩大产品入口；不将GroupAlreadyEstablished或ConflictingOrigin直接改成成功。非零位置创建和显式冷接入不能复用已消耗的一次性预密钥，替代组须取得新认证材料；旧换钥可能生成与新组位置冲突的ACK，因此退役接收必须拦住出站控制，而不只是保存第二份快照。

<!-- tao:field consequences -->
**初始授权快照:** 本人私有关系/能力页不能抢在来源已知的吊销原件之前赋予目标旧设备绑定。来源按本用户及当前页涉及的用户检查定向吊销投递；只有目标在保存用户签名原件后发出的设备认证确认全部持久化，才允许准备和提交该页，原密文重试也重新检查。证明通道独立运行，涵盖尚未建立、拉黑或已删除联系人的既有负面事实；对其它用户的证明只交给本人合法设备，不把负面事实当成建立关系。每页最多32条操作，检查沿固定五秒SQL预算执行，不将全部吊销列表塞进有限大小的关系页。提交期间新收到吊销须使旧准备失败，不能靠先前检查放行。该保证以来源准备/交接时已知事实及目标持久身份连续性为前提；已经交给网络的旧原件无法追溯撤回，来源尚未知的远端吊销也不具有全局即时效力。任意回滚同一设备密钥下的数据库不属于正常重启语义。

**联系人首次Create的吊销屏障（用户选择，2026-11-07）:** 保留既有隐私路由。本地用户签署且来源已知的吊销事实，若按现有合同需要交给本次联系人Create选中的单台目标设备，必须逐条由该设备持久化并认证确认；每条确认绑定不可变proof identity、目标设备和owner，不声称单条确认了整个事实集合。同一目标对同一不可变proof的已持久ACK可跨attempt复用；新的proof或不同目标仍需独立确认。候选准备捕获完整排序后的本人来源吊销事实集合（设备ID与签名原件字节）或其确定性摘要；提交首个Create时在同一事务重查精确集合相等并逐条确认所选目标对当前集合均有对应持久ACK，不以行数或最大字段代替集合CAS，同时独立重查当前owner、scope、attempt、固定期限和额度。联系人用户签署的自身吊销事实仍仅在本机设备间同步，不路由给联系人设备，也不要求该contact bootstrap attempt等待其ACK。收到联系人的私有设备同步不会因此变成联系人目标的负面事实传递。此边界只保证本机当前已知、按现有路由合同需外发的事实；不声称本机已获知联系人的全部撤销，也不引入跨联系人设备的Peer事实路由或全局即时撤销。
```
