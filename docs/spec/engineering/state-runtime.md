# 状态运行时、所有权与序列化边界

<!-- tao:section overview -->
## 目标与适用范围

本篇是用户于2026-11-17要求全面重构后确定的目标设计，不表示基线`3330e0d954`已经实现。它补充[总体架构](architecture.md)、[消息](messaging.md)和[本地存储](local-store.md)的状态所有权与表示边界；唯一实施任务集见[重构计划](../plans/2026-11/20261117-typed-state-runtime.md)。切换完成时同步修改这些既有设计中的旧接口描述，不能让目标文档冒充当前实现。

目标是消除内部快照往返、大对象深复制和逐消息重复读取完整状态，同时保留当前授权、删除、可靠投递、崩溃恢复及资源边界。不通过增加窗口、重试、期限、切换优化构建或缩小工作负载取得通过。

用户明确选择：删除清理直接作用于待提交的结构体，最终只编码一次；成功提交后缓存同一个最终对象，不在提交后修补另一份缓存。

## 边界与数据表示

### 允许编解码的真实边界

- 网络表示：对协议帧、消息内容及必要的认证封装编码或解码。准备必须与效果一起持久化的冻结线包也属于此边界；重试和转发保留原签名字节，不重新封装冒充原件。
- SQLite持久化：读取时恢复结构体，写入时编码最终结构体。行回调可借用BLOB完成解码、摘要或验证，直接返回最终对象，不先复制完整输入再立即丢弃；确需跨行寿命的规范原件、精确CAS或待发载荷仍保留真正所有权。没有变化的状态不因检查或缓存计量而重复编码。
- 密码学表示：加解密、签名、验签、哈希需要的明确规范表示。编码方法和被认证范围必须由协议定义，不能把任意内部序列化结果当成规范表示。
- IPC、配置和文件导入导出：显式DTO与外部格式；不得让原始网络帧绕行WebView再回到Rust完成本应在后端执行的协议处理。

除上述边界外传递领域对象、已验证输入、状态候选、标识或只读视图，不以完整序列化／反序列化实现对象复制、读取少数字段或跨模块适配。密文、签名、摘要、附件内容和精确签名原件本身可以是字节数据；要求它们有明确类型和所有者，不是禁止所有`Vec<u8>`。

发送调度使用已有的类型化效果、内容／历史所有权及精确的首次Create关联，不从冻结网络原件反向猜测类型。Create关联在真实构造事务内绑定候选、目标、授权代次、反向公告序号与原件身份；维护、重连及重试只查询当前仍有效的结构化事实。兼容旧持久输入所需的原件验证只在一次性SQLite／会话恢复边界进行，完成标记与关联原子持久化，不以每轮调度补解析作为回退。标签不能代替密码认证或当前授权；原件字节仍由同一个不可变所有者共享，持久化后原样出站，不为调度重新编码或复制大载荷。

### 编译依赖与可信适配器

`yochat-core`定义业务、事务和协议后端所需的窄契约；`yochat-protocol`实现具体群状态、密钥和表示转换；应用层组装运行时。Core不反向依赖`yochat-protocol`或具体群加密库。隔离依赖不要求继续使用快照字节作为内部通用接口。

需要真实加密后端的SQL原子性、加入账本和模型对拍用例归入`yochat-protocol`的后端契约测试；Core自身的纯业务测试仍留在Core。不能为了测试方便添加Core到协议适配器的反向开发依赖，导致依赖隔离失效。

采用核心契约加协议适配器的结构化候选提交。候选在Rust类型上持有工作状态及所基于的会话、上下文和版本；协议适配器检查结构体中的密钥、定序区间、创建者和授权绑定，Core检查当前关系、许可、设备、删除事实及版本。不能接受调用者自报的`validated=true`或未绑定对象的元数据。

具体加密状态由解锁身份所属的后端运行上下文拥有；不把加密库字段写死到Core的`Store`。Core定义带会话状态、设备协议状态关联类型的`CryptoBackend`，Protocol提供实现，`Store`保持非泛型，事务方法对后端泛型化。后端提供结构化检查、原地清理及真正存储边界的编解码；独占工作区持有候选，借给事务修改，成功后保留原对象。

检查必须同时覆盖当前`BootstrapCodec`承担的创建者、选中候选、上下文、授权和缓冲引用绑定。Core仍在事务中重查关系、设备、删除与CAS事实，准备安装仍使用私有捕获票据；不能只迁移`CryptoSnapshotCodec`的两个字节回调而遗漏安装来源检查。

入站关联类型`CryptoBackend::Incoming`同时持有冻结原件与由它验证得到的结构化消息。Protocol的`channel::VerifiedIncoming`只允许通过`open_incoming`构造；分类、授权、接入安装、保留上下文处理及执行器借用同一个对象，不分别传入可能错配的原始字节和验证结果。`IncomingMessage::bound_frame`与控制／密文消息共享同一个已验证上下文。物理字节入口`deliver_inbound_frame`在准入后验证一次；验证失败仍走真实坏包记账，不调用业务解码回调。

设备协议行没有独立版本列，依靠身份内唯一写入所有者协调；不得声称可用会话版本检测设备密钥的并发覆盖。`put_protocol_state`、bundle的offer／accept、联系人bootstrap offer和独立删除事务也必须迁移，不能留下绕过缓存的持久写入口。

设备级CAS使用`ProtocolRevision`携带Store开启代次与进程内单调修订；加入尝试和准备承诺均绑定这份预提交修订。事务先核对期望修订，不能读取整行设备状态BLOB或重新序列化含HashMap的对象来比较。携带设备候选的事务成功后才发布修订，即使该事务不需要重写协议BLOB也保留既有提交围栏；业务`commit_seq`、会话版本和设备修订可分别推进。该令牌不持久化、不跨Store重开复用，也不代替活动／保留／等待会话各自的SQL版本。

`p2panda-encryption`的密钥管理器、登记表及Protocol准备记录按实际变更设置仅内存的持久化标记；借用查询、只读探测和无变化操作不能把状态标脏。编码、清理及失败不能清除此标记，只有SQL提交成功后才在同一最终对象上确认持久化。已有协议行且候选干净时跳过全量编码／更新；行存在性由工作区单独记录，因此从文件恢复的干净对象首次导入空数据库仍必须写入，不能把“解码后干净”等同于“该Store已经保存过”。

会话准备密钥通过有界同步作用域的所有权覆盖层临时供密码操作选择，不把预留包反复插入普通登记表再整表取出／归还。只读探测仅复制选中的固定大小公开包，普通操作消费选中的预留；作用域结束后保留真正未消费的对象。消费过的预留也须在作用域结束前参与重放识别，避免同一包在回调内重新流入普通队列；错误及panic退出均清除作用域记录，不发布未提交候选。

`p2panda-encryption`补丁提供字段的结构化借用视图和消费式更新，不再在应用侧维护可序列化镜像。设备密钥管理和登记表通过所有权进入／离开一次群操作；错误后不能返回表面有效但部分消费的`Protocol`。明确保留坏AEAD及错误明文绑定不安装候选棘轮的保证。

### 单一所有者与缓存

每个解锁身份拥有一个运行上下文，沿用现有实例／用户／设备／解锁代次票据。逻辑上包含：

- 每设备一份`Protocol`：密钥管理、对端预密钥登记和准备密钥保留。它跨会话共享，不能复制到各会话缓存。
- 每个活跃会话一份业务状态和选中加密上下文状态，连同持久版本及业务提交修订。
- 显式有界的缓存工作集：包括前台会话和后台收发、补缺、历史作业涉及的会话，而不只跟随当前UI选择。

业务缓存键必须保留`machine_state.instance`的实际含义：当前应用收发用会话十六进制值构造Core的`InstanceId`，不是身份目录的实例名。业务状态携带`commit_seq`，加密上下文携带各自版本；不能把所有会话的业务状态错误合并为身份级一份，或把三类修订当成同一版本。

只更新接入尝试／准备承诺的事务不写业务`State`或提升其`commit_seq`，也不能驱逐现有业务缓存；设备协议候选提交仍使用自己的`ProtocolRevision`围栏。业务状态即便携带较早的快照，也不得借这类纯准备事务覆盖已提交的消息和游标；必须在编码之前判定此分支，而不是编码完整状态后再丢弃结果。

每个会话状态由一个操作独占取走、更新、提交并归还；共享设备协议状态同时受同一身份的写入所有权约束。不增加锁内网络等待，不在两个互相独立的缓存锁和Store锁之间建立反向获取顺序。暂不以多会话并行取代现有串行保障。

缓存命中后不重复读取或解码同一份完整状态。所有生产写入口必须参与相同的候选／提交／发布协议，包括Core执行器、会话重建、准备接入、候选安装、历史导入、直接发送、删除及保留上下文清理；不能只包装`handshake::decode_inbound`。

接入确认只读取所需的版本元数据，不为取得版本重新恢复已在独占操作中的加密状态。执行器没有推进业务状态的成功提前返回，同样归还取出的原业务对象。UI状态投影借用已核对提交修订的业务缓存；冷读恢复后交回运行时，不为多个状态字段重复解码整份`State`。

放弃缺失原生位置分为业务决定、上下文维护与原件重放。业务放行决定与持久放弃意图仍在原业务事务中保存；`Store::apply_crypto_abandons`只维护加密状态，不取得或驱逐业务缓存，不写业务`State`或提升`commit_seq`。重放产生实际业务变化时仍走业务提交契约；真实首次非元数据业务提交仍原子初始化状态行及修订。

维护分别处理活动、保留及残余Waiting状态，按状态种类重查当前权限、来源约束、工作区代次和SQL版本，在各自固定预算内清理并CAS提交；只有发生变化的最终对象才编码，成功后归还原本已热缓存的同一对象。Waiting只记录放弃事实，不取代其后精确原件和授权凭据的激活复核。各上下文维护及重放是独立原子事务，后一步失败不撤销此前已提交的进度；所捕获意图保留至本轮选中的真实原件在各自上下文重放成功，再原子清除该捕获集合，不删除后来新增的意图。不激活保留上下文或发送其ACK；重放成功也不表示其他缺失依赖或网络交付已经完成。

活跃上下文的合法因果缓冲可以超过保留上下文清单的256项上限；放弃维护不能把两者混为同一准入条件。活跃上下文只选择按作者／原生位置排序的首个待重放原件，并点查日志与协议等待行核对其精确哈希；缺失、坏哈希或相互冲突的来源仍拒绝。保留上下文继续验证完整清单及原256项上限，Waiting不产生重放。选择原件不表示正文已交付，持久意图仍须等真实重放成功后才清除，原SQL预算不变。

保留上下文先核对来源、选择与当前SQL版本，再取得匹配的缓存对象；命中不读取完整状态BLOB，未命中才恢复。接入准备同样取得带业务提交修订的唯一`State`，通过`PreparedBootstrapInstall::take_business_state`移交执行器，不在准备与派发两段各恢复一次。预检查、提交修订和失败丢弃围栏保持，准备对象不能提前发布。

缓存不成为授权事实的替代来源。冻结发送在真正出站时仍重查当前授权；会话状态存在不表示目标仍获允许。

### 内存边界

缓存使用显式总内存预算及可确定的淘汰规则。计费覆盖嵌套缓冲与容器容量，不以`size_of<Vec<_>>()`或条目数冒充实际占用；禁止为计费而序列化整份状态。预算及权重算法在实现前由保守内存投影确定，并以保留密文的压力输入校验。

只淘汰没有操作借用、已可靠提交的条目。单个状态不适合留存时允许不缓存，不能删掉未决依赖、伪造完成或提高原接收／存储额度。活跃操作的有限工作集仍受原消息、数据库和协议限制；淘汰不能造成无限等待。

锁定、空闲过期、身份替换和旧代次结果拒绝时释放相应缓存与密钥。不可变共享只用于确有多个所有者的数据；不能用共享可变大状态隐藏深复制、延长已撤销密钥寿命或破坏单所有者。

## 候选与事务契约

### 一次状态推进

1. 校验身份票据和入站准入；从缓存取得当前状态，未命中才从SQLite恢复。
2. 在本次独占候选上执行业务和加密转移，收集原件、设备协议变化、待执行效果及受影响状态。纯状态机可以消费拥有所有权的状态，仍不做IO、读时钟或取随机数。
3. 事务依据本次最终业务行、删除标记、引用绑定和授权事实，对当前、等待及保留上下文的结构化候选做删除清理。需要触及的非缓存状态在SQLite读取边界各恢复一次，随后仍以结构体操作。
4. 对最终候选执行协议不变量和当前授权／上下文／版本检查。删除清理后再次确认被删除的材料不在候选中。
5. 每份有变化的最终状态编码一次，与业务状态、协议状态、原件、计时器和冻结效果同事务保存；原CAS和SQL截止不变。
6. 提交成功后把同一个最终结构体及提交后的版本交回缓存，再执行已持久化效果。无变化的状态不产生快照写入。

不能先编码、在事务末尾改写字节快照、再缓存编码前对象。基线中的`crypto_snapshot::scrub`可能在同一事务已经递增版本后再次改写内容而不额外递增版本，因此仅比较版本不足以证明调用者对象与最终行一致。目标实现必须消除这种生产写路径，不以提交后重新读取或补丁式修补缓存作为正常方案。

独立删除和上下文安装同样服从本契约：删除取得受影响热状态的独占对象，清理后随事务成功归还；安装将原活动对象按需要移动为保留上下文，新候选成为活动对象。非缓存行只在真实存储边界恢复。不能把成功后的全面失效／重新读取当成正常清理方案，或在移动保留上下文时复制整个群状态。

### 大对象与回滚

`GroupState`、`Protocol`、业务`State`、缓冲消息集合、正文及线包不得因内部接口便利被整体深复制。以移动所有权和借用传递；只读共享句柄的引用计数增加不是深复制，但其使用必须有真实多所有者及资源寿命依据。定长标识、必要的小密钥候选和有界局部元数据可复制，不能把动态大容器包装成一个小指针后宣称其深克隆很小。

失败后不能发布候选。若工作状态已被消费且无法无损撤销，则丢弃受影响的缓存，从已提交SQLite状态恢复；共享设备协议状态也必须失效，不能继续使用已暂时消耗预密钥的对象。预验证拒绝应尽量发生在取走工作状态前，避免攻击者诱导无关会话的全量失效。

保留小范围操作级密钥候选的安全语义，尤其不能因禁止大对象克隆而让坏AEAD或错误绑定消耗持久棘轮。不能用全状态克隆或中间快照代替明确的失败处理。

TLV解析返回借用字段，编码借用正文／密文；规范性由标签顺序、唯一性、已知字段及精确长度校验，不通过全量重编码比较。生产发送使用`channel::seal_signed`的借用最终化路径；Bound封装直接把规范Envelope写入带前缀的最终缓冲，不生成另一份完整密文Envelope或中间编码Vec。解密后复用原明文分配，结构化快照直接写入带前缀的最终输出缓冲。

好友应答的`reply::ParsedReply`只借用原输入中的TLV字段；外层完整规范性检查得到的同一视图供邀请标识路由、开封和验签使用，不为每个阶段重新解析或复制正文。收到的规范资料原件经完整验证和流式规范字节比较后可保留同一分配；非规范输入仍生成真正的规范表示。

控制反应从`p2panda-encryption::GroupEvent`移动到Protocol，不能通过线程局部字节捕获、编码／立即解码再筛选。移出本机事件保留密码库已经生成的真实控制输出；适配器保持原正文、移出标记、隐藏确认与可见控制的相对顺序。保留输出不代表成员协议必须接受“确认自身移除”：`AckingOwnRemoval`拒绝及简化测试网络的原忽略策略不变。事件专用接收不构造调用方不消费的成员前后集合或差分，完整成员输出入口保持原语义；密码处理必需的成员判断仍执行。最新预密钥选择直接迭代，不先收集整份临时指针集合。

补发Effect的JSON在一次流式访问中校验元数据并比较载荷，不按同长度原件候选数重复解析。原件候选通过单个只读SQLite BLOB句柄重开定位，以两个固定1KiB缓冲精确比较；不以摘要或长度相等代替原件相等，不物化所有候选密文。SQLite查询与Rust扫描共用原固定截止，当前目标、授权、密钥代次、删除及发送所有者判断不省略。

历史摘要流式写入规范JSON对应的哈希输入，不生成完整JSON缓冲。SQL源项保留证书的同一规范字节，摘要、线包编码和派发复核借用它们，不解析后再编码同一父集合。到期判断先读元数据，未到期不恢复历史块；待发窗口用SQL计数和有界读取，不先恢复全部未确认块。Store一次物化不可变`PreparedHistoryChunk`并捕获发送复核所需证据；发送事务仍重查当前授权、作业取消、冻结计划、删除及原件／正文绑定，但不再次读取并构造同一份完整块。接收侧`VerifiedHistoryChunk`只证明摘要和结构已经检查，不代替签名、授权或事务内当前事实。准备类型不能由任意原始块构造，也不证明一个独立传入的加密`SealedTo`一定包含该块；真实生产发送方必须直接编码并加密同一个不可变准备对象。

生产历史接收用`HistoryChunk::decode_retained`在真实线包解码边界保留每项证书的不可变规范表示。块摘要、正文或已删除项身份认证、原生位置提示及最终SQL关联移交或借用同一`CanonicalOrder`，不丢弃规范字节后重新编码父集合。凭据须绑定实际项和声明，不能把对齐的字节槽当成已认证标记；独立原始块／证书入口仍自行验证。

顺序补证的出站页按已有规范证书与见证的长度增量装箱，不克隆或编码增长中的整页试探容量。`PreparedMessage`独占领域消息、最终规范字节及从这些字节计算的页摘要，调用方不能分别提供不匹配的对象与摘要。首次领取直接移交本事务刚保存的对象；重试从SQLite恢复原字节，不重新编码。发送前后仍分别重查授权、固定租期、修订、作业所有者与已领取页摘要，不把表示验证当成当前授权。页面、消息及根签见证的深克隆仅对测试特性开放。

联系人出站页以私有不可变`PreparedBatch`保留增量计算的精确线包长度，最终编码直接写入预留输出；事务不重复计长序列化。公共未准备批次仍执行完整验证，准备证据不代替来源、权限、能力、吊销和配额复核。

联系人与历史删除页的`contact_delivery::Received`私有绑定不可变领域消息及从真实载荷字节计算的摘要；大小检查、ACK规划及落库复用该证据，不反复整页计长或重算摘要。历史删除出站页只在最终线包边界编码一次；流式比较／哈希不生成另一份完整编码。原始不可信入口仍独立检查规范性与边界。

补证ACK只读取已验证且不可变源页的有界头部和总长度，不恢复整页证书与见证。头部必须覆盖双游标及最大检查点计数字段，并继续绑定请求范围、页号、游标、页摘要、已发送次数和当前作业；该快捷路径不能用于任意未验证网络页，也不替代租期、所有者或当前授权检查。

根签见证在构造／读取边界验证并保存同一不可变对象的规范JSON及摘要；排序、落库和页编码借用它们，不反复序列化设备名单。补证解码通过定宽字段、精确计数／标签、嵌套规范解析与跨字段约束判定规范性，不整页重编码比较。未来页保留仍执行原页大小上限，长度检查不生成完整线包；单独计算页摘要时流式写入哈希，不分配另一份完整页。

控制接收通过`Envelope::decode_borrowed`和`Payload::decode_fields`借用已验签原件的内层字段，直接交给控制解码器，不先复制整份信封内容和控制字节。`PayloadFields`只证明外层规范结构和字段上限；具体载荷仍由相应解码器完成语义验证。控制帧继续核对签名日志、作者、位置及依赖，控制字段仍受65,535字节上限约束。恢复通道的历史块同样借用解密明文中的字段，再一次构造最终历史项，512KiB块上限不变。

密文接收在原生操作边界直接取得解码后的正文分配，验签后将同一分配及密文范围移交定序对象，不先包装成不可取出分配的中间`Body`再复制。内存预算计入完整后备容量，快照只编码可见密文范围，避免把信封头写入历史快照。原生及引导控制输出直接流式写入最终带前缀正文并回填长度；65,535字节控制上限仍在编码时强制执行。

`p2panda-encryption`的拥有型AEAD入口消费明文／密文分配，复用缓冲并为认证标签预留空间；失败仍遵守原候选状态与密钥安装规则。`NoKey`保留并返回原密文分配，而非先复制一份供恢复。证书与正文直接借用字段编码到最终载荷，不能为随即丢弃的临时`Payload`深复制大父集合。

历史恢复的X3DH发送消费独占明文分配，前缀和认证标签空间在构造时预留；保留确有独立小密钥材料消费者的借用入口，不为大历史明文另建副本。普通线包的规范CBOR直接在最终字节向量与整数数组之间转换，不构造逐字节的通用Value整树；原线格式、规范整数、标签／深度、长度和完整消费检查不变。


顺序补证的入站页由`ReceivedMessage::decode`从规范线包生成`ReceivedPage`，页摘要绑定同一份输入，字段不可分开替换。暂存、领取与接纳移交同一页面及证书集合，不复制整页或重新编码以重算摘要。准备凭据不代替事务内的权限、租期、游标、重放和配额检查。源页先按索引选择见证位置，同一签名批次每页只读取、解析并缓存一次；仍校验索引用户、规范字节及摘要匹配。

迁移安装从已经加载的会话捕获上下文、原件身份及状态版本，私有`MigrationBinding`保留一次验证的来源证据。后续所有权和事务检查重查当前授权、选中上下文、版本、必需参与者及保留容量，不重复恢复完整会话。重放原件及迁移来源通过SQLite精确字节比较确认，没有把“摘要列未变”当成“原件未变”，也不为比较把整份原件读回Rust。独立冷校验仍在SQLite读取边界恢复会话。

排序证书的认证及因果解析可借用同一不可变`OrderCertificate`，认证结果不能被换配到另一份证书。来自规范边界的证书由私有封装共同持有原字节与摘要；认证、依赖闭包、排序／正文写入及历史关联复用该表示，不在解析后或每个阶段重编码大父集合。认证产生的规范凭据须移交后续消费者，不能丢弃后立刻重算。历史正文认证、已删除消息身份核对、发出证书自检和接收预检均不为消费式接口复制大父集合。真正需要独立持久对象的入口保留消费式所有权，签名、内容绑定、引用、前驱、父高度及固定预检截止不省略。

实时接收的`PreparedApplications`移交并封存释放操作及其正文认证证据，只允许对同一不可变证书、作者、正文、引用和开封材料复用。事务仍检查当前授权、父项、墓碑、配额及原子提交；原始操作转换入口没有该凭据，必须独立认证。共享或保留原件的证据不能由可变摘要列替代：精确原件比较每个准备／提交阶段只做一次，但每个转发目标的当前授权与删除栅栏仍分别执行。


大范围删除把标识集合的所有权移交本地动作；确认存在本人其他接收设备后才构造传播内容。同一份最终位置JSON用于指令标识和指令载荷，保持原字段大小上限、时间与失败语义。接入准备探测用postcard的只计量输出验证实际序列化，不分配随成员历史增长的临时字节；它不代替真正发送处的载荷大小检查。

接收正文的密码验证结果由`AuthenticatedHistoryChunk`持有，通过同一`HistoryChunk`的不可变验证视图绑定证书、正文、声明时间、引用与开封材料。Core只能消费与实际写入项匹配的私有凭据；正文的原生位置提示和正文写入复用这份认证，不再次验签和哈希整份正文。凭据不表示当前授权、排序父项、墓碑、配额或恢复计数已经通过，事务仍重查这些事实；无凭据的原始导入必须自行认证。原件验证和`SourceDeleted`的身份验证不被正文凭据替代。

每项历史认证槽在单次消费正文凭据后仍保留已认证的32字节排序摘要，收据辅助来源更新直接使用它；摘要仍绑定同一块、作者及项所有者，不能重新消费正文凭据。保留上下文接收也移交私有不可变正文／受保护证书证据；顺序游标核对实际原件位置、作者、时间和正文所有权，失败拒绝事务而非回退重复认证。通知使用同一已认证摘要；当前权限、原件精确摘要、版本及CAS仍在提交时检查。

### 网络与UI

接收缓冲从网络队列移动到Rust协议处理，验证、持久化及生成UI事件均在后端完成。UI只收到明确的消息／进度／错误DTO，不收到待重新提交的原始网络字节。

异步发送需要拥有冻结帧，借用接口导致的整帧`to_vec()`须改为所有权转移；确需多目标共享时使用不可变共享缓冲，保持每个发送尝试的原有额度计费和租约寿命，不因共享物理内存提前退款。MemoryBus及真实端点遵循同一契约。

`yochat_core::net::FrozenFrame`提供冻结帧的不可变共享所有权：从`Vec<u8>`接管分配，克隆只共享字节；`storage_capacity()`保留移入分配的容量，与逻辑长度分别计量。帧相等只比较字节内容，不能因分配容量不同而把相同原件判为不同。JSON边界沿用字节数组表示，不持久化进程内容量；反序列化后按新分配计量。

真实QUIC发送消费冻结帧的`Bytes`并交给`write_chunk`，不经`write_all`重新复制。接收通过`read_chunk`取得有界数据块，能立即获得容量时直接追加最终帧；压力下只复制当前最多8KiB的数据至暂存，并在等待容量前释放共享网络后备分配，不能跨等待保留未计费的大后备缓冲。

接收大帧按有界增长策略预留容量，必须容量与可选空余容量在同一次预算判断中选择。可选空余不足时立即退回可容纳的精确需求，不能因为优化而等待、失败或延长读帧截止。真实分配容量的租约跨越读取、FIFO和消费者寿命，取消、截止、错误及最终释放沿原计费规则退还。

保持真实来源身份、逐对端FIFO、跨对端服务、批次上限、逐帧错误隔离和原维护节奏。删除旧生产原始帧IPC接口并迁移全部调用方；必要的故障注入为明确测试接口，不保留旧入口作兼容别名。设备新增／吊销的普通IPC只返回完成状态，不向UI返回随即丢弃的完整包；真正转发原件的验收调用方使用仅`e2e`特性开放的独立取包命令。

消息到达DTO只携带会话、作者、消息标识和状态，不夹带正文再经WebView送回Rust通知命令。后端在身份运行时锁释放后执行通知；前台、静音或不显示正文的通知不读取正文，确需后台正文时按已提交消息标识从SQLite读取。通知失败不把已经提交的网络消息变成可重试接收失败。联系人Bundle等待项直接共享冻结帧并按保留容量计费，满足条件的项从缓存移动取出，不克隆整项。

网络屏蔽更新借用传入集合完成连接、到达队列及地址清理，再于同一锁定范围内移入新集合，不在队列锁内深复制整个集合。非法用途标签只在错误中记录长度，不持有或格式化攻击者提供的完整标签。

设备名单只在存在到期且获准的收件人后生成签名原件，多目标共享同一原件；无目标和未到期不能先封包。接收时恢复一次`DeviceList`，路由、本人身份检查及名单应用借用同一对象，仍分别执行原签名、来源和吊销检查。合并验证以借用批次及条目投影比较规范结果，指纹流式写入哈希，不克隆整份历史证明来验证自身；被覆盖的操作仍逐批验签。Store通过绑定精确前驱的私有验证结果执行观察，不再为确认派生并集重建同一大对象。归档先借用扫描已有批次，仅为缺少作者证据的批次生成有界规范字节；真正产生独立的合并结果时才物化所需条目和证明。

认证后的名单更新先比较借用的规范批次并集，完全未变才直接返回；真正变化时再物化拥有型结果。延迟名单观察在完成原验证后，仅为需要保存的远端未公告加入证据流式计算规范JSON的SHA-256，不为摘要分配整份名单JSON，也不借观察提升成员资格。

已验证设备名单的证书和归档生成借用同一名单，不为每个条目重复构造验证对象。仅需opening成员关系和版本的路径读取SQL窄事实，不恢复完整名单。保留帧的精确比较使用有界读取证据，不为验证一次原件而把整帧复制进Rust。

设备名单重试先读取精确签名和到期元数据，存在到期目标才恢复完整名单；恢复及生成包后重查同一签名，只为被网络接受的发送记账。计数、设备标识、展示条目及选中别名／编辑令牌从同一已验证持久名单读取窄投影，不恢复保留证明；当前准入排除吊销设备，历史本人资源归属明确保留它们。这些投影不认证新线包，也不表示SQLite不读取或解析原JSON。

联系人引导的版本与单设备成员判断使用同一窄事实读取，保留精确u64版本和opening提交时的观察值CAS。本人资源归属以固定截止内的流式设备ID读取跳过别名和签名；历史已吊销本人设备仍参与资源分类，本机回退单独保留，不能用累计对端登记表扩大本人额度豁免。

需要完整名单的同一授权批次最多恢复并验证一次当前本人设备名单，按需共享给联系人、历史、密钥同步及迁移参与者检查；常规授权优先读取所需元数据，撤销状态仍逐次查询。名单缓存不跨事务，也不跨名单写入边界；普通journal不修改名单，独立名单安装事务结束后下一批重新读取。授权按需读取真实身份，不使用配额记账可能省略的本人用户占位值。名单签名与所属用户必须匹配，不能把数据库行键当成授权证明。热会话维护优先复用workspace内同版本状态，仅在名单变化需要推进时加载并修改候选；未知引用的删除状态按原拒绝规则处理，不能用省略查询放行。

无引用授权只读取元数据；新引用按实际目标取得一个删除事实，未知作用域仍失败关闭。就绪重放先取得一个有界拥有型效果批次，再对同一批次授权并借用执行，不二次选择不同作业。完整持久Send探测按实际已校验grant点查引用删除状态，不能复用已清理或不同源消息的引用作用域；`Authorization::recheck_stored`默认委托原`recheck`，保留自定义授权拒绝。固定应用响应批次在首个封装前验证一次当前成员，空批次不新增检查，实际成员变更的独立验证不合并。

加入看门狗消费过期处理返回的同一份已更新清单，任务原地推进；失败恢复仍从持久状态重新读取，墙钟观察及固定截止不省略。

`JoinAttempt`与`JoinPromise`消费旧状态并移交最终状态；是否变化不靠克隆整份旧候选判断。scope、签名收据、决定及网络输出借用不可变视图，bootstrap安装直接验证所需元数据。真正独立执行的准备快照仍拥有自己的状态，不能以共享可变状态破坏失败回滚。

加入交换在提交前保留已通过大小预检的最终编码，提交后当前授权通过才发送同一缓冲，不再重建相同请求。设备准入把同一已验证前驱交给一次名单并集更新，持久化、观察和见证复用该更新；已被当前名单包含的旧准入名单仍是无变化，普通名单写入仍拒绝版本倒退。准入签名直接写入带标签的最终缓冲，正文大小上限单独计量。

资料快照每个候选只解码一次，以规范候选集合和`current_index`表示当前项，不能另放一份相同头像／别名的当前对象。Core的`Snapshot::current()`返回借用；App将候选所有权移入IPC DTO，UI按索引取得当前候选，不假定排序首项就是当前项。冲突选择、编辑令牌CAS、头像上限和不可直接覆盖冲突的交互不变。

冷读或变化后的资料快照在SQL确定原始字节顺序及选中项优先级，逐行借用BLOB校验、更新精确原始令牌并生成最终候选；Rust不同时保留全部原始JSON及已解码头像。令牌仍覆盖非规范原始字节和完整候选集合，不能以SQL排序或规范摘要代替原始CAS；SQLite自身的排序工作不因此消失。

本人及联系人资料轮询先读取小型完整新鲜度元数据，覆盖选中摘要、版本、冲突候选、溢出状态，并绑定当前身份／编辑权限或关系代次／屏蔽状态。标记相同时不读取头像正文且IPC返回未变化；UI保留原对象和预览，拒绝选择、身份、代次变化及销毁后的迟到结果。新鲜度标记不代替编辑令牌CAS或当前授权，空资料出现及同版本冲突也必须触发更新。

联系人总览在UI共享同一只读列表，不由两个常驻组件分别恢复并传输。完整修订游标覆盖实际展示字段，并处理身份切换、外部数据库写入与时钟回退；未变只返回小型游标。验证复选状态绑定当前关系代次，并使用Svelte可观察映射，不能因非响应式提前返回而漏掉按钮资格更新。批量删除决定仍逐项提交并保留失败前缀，列表只在整轮结束或失败后刷新一次。

邀请轮询在同一读取事务核对私钥能力、邀请记录、作废及签发设备吊销。变化快照逐行从借用BLOB认证一次；Store范围的TEMP触发器修订与`PRAGMA data_version`共同覆盖本连接和外部写入，重开时更换作用域。未变化只返回修订与能力，不重复传输列表。UI保留原列表，时钟单独更新有效期；创建／作废后的权威刷新、身份或权限变化、销毁和迟到结果受代次约束，轮询不能覆盖更晚的权威读取。

共享联系人对象的归一化搜索字段按不可变对象身份缓存，查询不反复遍历大备注／别名；聊天列表与交换页各自保留原账号资格规则。

资料广播和入库版本／冲突判定读取摘要、版本、长度等元数据，不先加载所有头像和别名。读取或接收的资料经边界校验后由`ValidatedProfile`持有同一不可变资料、规范JSON及摘要，传输和落库复用这些字节；网络非规范JSON仍先规范化，不直接保存网络原字节。SQL规范原件读取严格校验后移交原缓冲，不丢弃它再编码；原始资料入口保留验签、大小和版本校验。冲突选择只恢复选中的正文，以候选元数据与原始编辑令牌执行当前CAS，不隐式解析未选中的大头像。联系人公开别名在构造DTO时移交所有权，不另复制大字符串。

资料编辑只检查原件版本、数量和精确原始令牌，不恢复被替换的大头像。写入返回拥有最终资料的`CommittedProfile`；响应在同一读取事务核对当前身份、完整新鲜度及原始令牌，匹配才移动复用该资料，否则读取真实最新快照。不能用刚写入的版本号忽略同版本新原件、原始内容变化或编辑权限变化。

资料分块发送移交已经拥有的`Chunk`，不复制分块正文；遇到Busy不推进发送游标或截止。资料交换在外层借用字段上完成绑定并只解析一次内层`profile_transfer::Message`，接收运行时消费该类型化对象。生产发送从同一不可变消息校验绑定并编码，不立即解码刚生成的JSON；原始字节入口仍独立解析并校验不可信输入。

仅需原生操作事实或资料路由提示的入口流式检查完整外层编码和字段边界，不先物化整份正文。未验签资料提示只供分类，不能充当认证、授权或内层JSON有效性的证据；真正接收入口仍完成独立校验。

重发范围的首轮可用性判定只查询原件是否存在且非空，不读取完整BLOB；真正获准提供的原件在发送阶段读取。元数据判定不能绕过当前授权、窗口和最终原件检查。

新引用由Executor一次读取墓碑感知的有界摘要投影：最多480个UTF-8字节，保留最多120个Unicode标量及NUL，不读取完整正文和原引用。空正文与不可用NULL明确区分；缺失／已删除引用在构造发送grant前规范化为无引用，正文仍可发送。完整正文读取只留给真实重传等消费者。

联系人关系与授权门禁使用共享的窄投影，只读取关系、删除、屏蔽及验证状态；展示视图才读取别名、备注和分组，通知只查询目标标签，点操作不恢复全联系人列表。同步消息从实际`OpenedOperation`解析为私有`Received`证据，绑定来源、日志位置、原件哈希及真实载荷字节摘要，Executor不再反复解析同一JSON；缺失、多余、重复或错配的证据仍拒绝。准备证据不代替事务内的权限、ACK和当前关系检查。

私有联系人同步只对获准操作生成一次有界规范JSON，大小检查随写入执行；相同事务中的原始BLOB比较借用原始字节，不让SQLite绑定再复制整件。屏蔽集合只读取所需别名字段，不恢复备注与分组。补发审批先通过重复项和额度门禁再编码；拒绝路径不为马上丢弃的大原件分配编码。

联系人出站页把期望操作的规范编码流式比较到借用SQL原件，不构造两份完整字节集合；不匹配后仍读取余行，保留后续SQL错误的原优先级。部分私有字段编辑只拥有实际使用的字段，但仍以类型化丢弃访问检查未修改字符串／分组，不能因避免物化而放过原先拒绝的坏数据。

审批按钮按ID读取元数据；排空先固定本轮已批准ID快照，再逐ID重查会话、批准和到期后才恢复位置范围。处理中新增或重建的请求留待下一轮，服务失败不消费批准。生产审批列表用类型化流式访问完整校验范围，只保留数量与时间边界，不恢复或向UI发送位置数组；真正消费精确位置的E2E调用通过仅`e2e`特性开放的选中范围命令读取，不保留废弃的全队列接口。吊销投递先用SQL建立标识关系并选择有界到期目标，再读取和验证实际选中的证明；空闲或无目标不恢复永久历史。

应答确认和拒绝按邀请ID与应答者公钥点查选中项，不为寻找一项解码完整待确认列表；选中坏数据仍报错，不相关坏项不阻止处理。确认事务仍以最新认证内容比较用户实际同意的对象，不能用先前点查结果跳过新鲜度复核。

联系人重试先读取摘要和发送时间，只有到期后才恢复原页及密文；恢复后再核对摘要与发送时间仍匹配该次到期判断。时钟回退仍按原规则可重发，实际发送前仍检查吊销状态，始终重发原密文而不重建消息。

本人设备加入授权由可变`OwnAdmissionGrantData`经校验转换为不可变`OwnAdmissionGrant`，共同持有同一规范字节和摘要。存储、回执和发送复用该表示，不为大小判断、摘要和封包分别重编码完整名单。共享句柄的克隆只用于真实多所有者；不可变表示不能与可变字段并存而失配。非规范JSON仍按原有语义规范化，签名、60KiB上限、来源／目标、有效期、版本CAS及阶段检查不变。

## 必须保持的不变量

- 缓存只发布最终已提交状态；提交失败不推进可用缓存、持久游标、确认或外部效果。
- 业务、会话密钥、共享设备密钥、原件及可靠效果的原子性保持；出站效果始终在提交后执行。
- 删除材料不能经缓存、当前／保留快照、迟到候选或可靠重放复活。
- 上下文替换与重解锁后，旧会话票据、旧候选和迟到结果不能重新填充新缓存。
- 热路径没有对象复制式编解码或大对象深克隆；成功缓存命中不重复加载完整状态。
- 重试使用原冻结字节和身份，不重新签名／加密；去重、授权、时间、窗口、额度和负载边界不放宽。
- Core业务状态仍是无运行时句柄的纯数据；缓存属于运行时，不进入领域状态的持久内容。
- 生产切换不保留旧字节适配链、镜像更新路径、废弃别名或双轨处理器。

<!-- tao:section errors -->
## 失败、取消与恢复

| 情况 | 必须结果 |
|---|---|
| 输入预验证拒绝 | 不推进密钥、业务状态或可靠效果，不失效无关会话 |
| SQL失败、配额失败或CAS冲突 | 回滚整笔，丢弃候选，受影响缓存下次从已提交状态恢复 |
| 删除清理失败或超过原工作截止 | 不保存半清理状态，不发送确认，不发布缓存 |
| 锁定、过期或身份替换 | 终止新派发，释放相应状态；迟到结果按原身份票据拒绝 |
| 进程在提交前退出 | 重启从旧持久状态恢复，无未提交成功确认 |
| 进程在提交后、效果执行前退出 | 重启重放原可靠效果，不能依靠已消失的内存缓存 |
| 操作期间取消或后端替换 | 沿固定截止及代次规则结束，不靠重开组件或扩大期限放行旧工作 |

<!-- tao:section verification -->
## 验证要求

先用Quint定义候选、提交、缓存发布、删除、失效、失败、取消、重启和迟到结果；记录固定时钟与公平调度前提，公开正向入口以`Checks`结尾并在清单登记实际安全和时序义务。将关键状态投影与真实Rust事务／运行时对拍，不能以类型检查或采样替代性质检查。

定向消费者验证必须覆盖正文、后继正文、授权拒绝、删除后不可恢复、真实Store重开及失败后的再次收发，而不只检查内部计数。迁移所有收发、历史、重建、接入、删除、UI和诊断调用方；移除只固定旧接口形状的测试，保留消费者契约。

性能对照使用同一真实加密输入、SQLCipher和匹配debug构建，分开记录恢复／编码次数、处理字节、线程CPU／墙钟、缓存命中／淘汰、失败重载和实际进展。缓存命中普通成功路径不读完整会话或设备状态BLOB；每个受影响最终状态每事务最多一次编码，条件镜像往返为零。观察内存预算与锁定释放，不以序列化计算权重或用release掩盖debug成本。

先做定向检查，完整必需检查留到可集成批次。旧native acceptance修正当前暂停；重构所需的接口迁移不降低旧场景的负载、断言和边界。完整重构完成后按原计划恢复剩余原生验收，前台独占仍须用户授权。模型和局部回放不替代原万条、故障及双方真实重启结论。
