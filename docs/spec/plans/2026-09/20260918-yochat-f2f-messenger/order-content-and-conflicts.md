# 排序证据的正文承诺、引用清除与身份冲突

<!-- tao:section overview -->
## 概述

这是[统一排序契约](ordering-and-attention.md#DOC_20261103_VE1ZM1QD1QP5NK51--contracts)的实现细化，承接相同身份不得先到先得、元数据不得授权历史正文、删除后证据仍可验证的既定要求。用户已授权在排序正确性范围内先Quint后Rust；本细化不另设性能承诺。{need}`TASK_20261103_2V3MVXW59AT6NJNV`承担前置模型，wire/store任务显式依赖它；实际结果由[计划验证摘要](../20260918-yochat-f2f-messenger.md#DOC_20260918_BFV4FCXTMM9MQRDD--verification)维护。

<!-- tao:section architecture -->
## 边界与架构

排序证书还必须绑定原正文，否则相同证书可被复制到不同文字上。直接公开正文哈希会让只获元数据的新设备枚举短正文，因此证书只携带带32字节独立随机秘密的SHA-256承诺，域分隔并编码长度。秘密随获授权的正文一起端到端加密传输，绝不放进排序元数据；正文删除时一并删除。安全性依赖CSPRNG、SHA-256的隐藏/绑定假设及Ed25519，Quint只抽象这些假设，不证明密码算法。

正文承诺绑定秘密、自称时间和原始UTF-8正文；证书显式签名保留引用目标身份，引用另用独立秘密承诺目标身份和原始摘要。证书作者/会话/消息身份及父集合仍由原签名绑定。引用存在时必须验证承诺且目标身份对应一条已验证父证据；原有引用的摘要及秘密可被完全清除，目标身份仍保留以维持既有回复提示；不允许换成另一引用。这样删除引用目标时可抹去摘要及引用秘密，再重封原正文而不改证书或排序。持久删除事实优先于旧原件，迟到的完整引用不能恢复已清除摘要。

<!-- tao:section contracts -->
## 接口与数据契约

当前证书只支持一个新版本，正文承诺必填，引用承诺显式可选；当前库格式同步变化，不读取旧证书。正文和引用秘密不在Debug/错误日志中输出。复制/重封沿用原证书与原秘密，不重新生成承诺。metadata-only接口只返回证书（含签名引用目标身份这一因果元数据），不能返回秘密、正文或引用摘要。

有效证书按（会话、证书哈希）保存，身份索引不唯一；相同身份的不同有效签名证书均保留为冲突见证，并持久隔离该身份的全部正文展示和创建引用资格。不得保留第一个为赢家。无效签名/非法高度/缺前置不会使身份进入冲突；有效第二证书必须和冲突状态在同一事务提交。正常正文到达时，正文、秘密、引用与可验证的证据同事务写入；缺前置只持久暂存，不进入可见查询。可见查询须同时连接本条完整已验证证据并排除身份冲突。冲突不是一个可展示的新消息。已有第一个正文须从查询结果撤下并推进视图修订，后续UI提示由既定补入/重排任务承接。

普通接收将正文、证据、秘密和引用接入现有Journal收件事务，与密码快照、签名原件、业务游标及可靠效果共同提交，不另外套独立事务。列表、窗口、定位、搜索、未读统计及历史导出都使用同一已验证且无冲突的确定序列；未验证候选不能经旧查询旁路出现，也不能回退到本机接收时间排序。{need}`TASK_20261103_0WMEGM30ANHCHYPK`和{need}`TASK_20261103_JWEZ4F37GZJ1765G`承接。

补齐一个原生前件可以在一次接收中放行整条已缓冲链。证书的1024个父节点上限及SDK32代接收窗口都不是本次放行正文的条数上限；不得把合法的批量放行误判为存储证明损坏。整批预检保留同一临时父证据视图及固定五秒SQL/单调工作预算，逐份验证签名、正文承诺、父集合和高度，不提交临时事实；不能按父节点上限拆成互相遗忘父证据的独立窗口，从而漏过跨窗口的非法高度。

正文及其签名证书已暂存后，父证据后来在本地验证完成时，正常维护必须重新派生该证书的合法排序键，不要求对端在线或再次发送相同正文/证书。每次沿用既有16项工作界限，按消息行轮转重验，不能让始终缺父证据的前缀饿死后面的可验证证书。扫描位置只在进程内保存，待验证证书仍在SQL中；重启可从头扫描，不能丢失工作。局部验证、网络来源水位及视图变化沿用同一固定五秒事务预算，失败或超期全部回滚，不能续租已有补证请求。已擦除正文的证书仍可验证后继，但局部重验不读取或恢复正文秘密；高度、自己的前条、引用及身份依赖不合法的签名声明仍不可见，冲突隔离及墓碑条件保持不变。

冲突证据仍可作为精确哈希指向的祖先验证后继，不能因拒绝保存第二证书而永久卡住合法其他作者；父高度仍按真实已验证节点计算。已隔离身份的证书重复或重新封装不解除隔离，重启不能遗忘。正文删除保留全部无正文证据/冲突事实。自己的前条或引用身份若有冲突，创建操作明确失败，不猜哪个版本。

## 不变量与正确性

Quint有限投影：四个有效节点，两个作者；0/1为同一身份的两种证书，其中1以节点2为父，节点3为另一作者的后继并引用身份0。全量副本和新设备分别检查；新设备仅获节点3正文，其余可收元数据。检查父闭包、完整冲突隔离、失败原子性、重启持久、元数据不产生秘密、正文不匹配拒绝、删除不复活、引用清除不改变排序、引用秘密删除。

模型把正确密码验证作为输入判据；Rust须补真实签名、随机秘密、错正文/秘密/时间/引用目标/摘要、旧证书和秘密不泄漏测试。纯类型投影不能代替实际SQL/加密链路。下游wire/store必须逐状态对拍，不能在模型通过后直接勾选接线任务。

原生批量放行的条数边界另用真实签名回归验证：超过单证书父节点上限的合法链须全部通过；已签名但高度非法的后继即使排在首项、其根排在旧批次边界之后，仍须拒绝。该边界不由四节点模型的类型检查或采样代替；实际拒绝密文还须通过普通解密及收件事务重放。没有新增异步等待或放宽既有截止期限。

局部重验另检查有界轮转在阻塞前缀、已签名但高度非法的证书、失败/取消及一次重启下的安全与条件进展。条件只要求所需父证据已在本地认证、正常维护最终获得成功调度及稳定运行窗口，不假设网络最终投递。真实SQL回归须覆盖子证书先到、父证据后到、关闭重开后不重放子证书也能显示原正文，以及超过单次扫描界限的阻塞前缀；无效高度不得因父证据出现而被发布。

## 失败处理

本模型动作是有界本地原子操作，不拥有网络请求或物理时钟；缺前置仍可持久保留正文，但不能展示排序键。条件收敛要求全部四个合法元数据最终被公平供应且有一次成功提交；没有该前提不宣称网络必达。实际SQL沿用固定五秒预算。异步补证的取消/失败/重启/迟到所有者及固定期限继续由历史任务的生命周期模型和真实Rust对拍承担。

业务线格式解析拒绝由{need}`TASK_20261103_0WMEGM30ANHCHYPK`和{need}`TASK_20261103_JWEZ4F37GZJ1765G`承接：原件已验签且群密码已成功解开、但明文无法按当前业务线格式解析时，原件、密码/协议状态、接收位置和拒绝标记同事务提交；不产生正文或业务送达回执，不把这次业务拒绝当密码故障重建。SQL失败则全部回滚。拒绝标记仅绑定该原件的会话、作者、位置与精确哈希，重复拒绝不再进入棘轮；普通有效消息原有的确认重发保留。仅历史导入原件不表示已交给本机群密码处理，不能仅按原件存在跳过解密。有限事务接缝另由native_application.qnt检查，签名/正文承诺及缺前置仍由既有模型承担。
