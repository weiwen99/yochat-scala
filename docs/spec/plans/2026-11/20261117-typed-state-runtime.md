## 设计与实施约束

内部消费／借用结构化对象，真实边界才转换表示。Core定义窄契约，Protocol实现具体状态，解锁身份运行上下文拥有缓存；禁止Core反向依赖具体协议实现，也不以不透明字节回避类型设计。

单次转移取得独占工作状态，将删除清理应用到最终候选，校验后每个变化状态只编码一次，同事务持久化，成功后缓存同一个最终对象。失败丢弃候选并使受影响状态失效；不克隆大状态作回滚，不在提交后修补另一份缓存。

先明确共用的候选、存储及所有权契约，再并行推进真正独立的Core纯转移、协议结构化访问、网络缓冲等切片。共享文件只有一个集成所有者。子代理不在编辑中途运行构建／格式化／测试；集成后由主代理运行一次定向检查。需要隔离实验时只在`.worktrees/<名称>/`建立工作区并使用自己的Cargo目标目录。

已知迁移面包括30个文件构造`CryptoCommit`、53个文件构造`StepCommit`（含测试），且存在共享设备状态及事务末尾删除改写，不能当成单函数替换。每个切片先依据方案、引用和过往执行记录明确可观测进展、检查点及停止条件；等待必须有固定截止。实验无业务进展或耗时明显偏离实现中的工作预算时，先检查调用时间线、锁、CPU及IO，缩小复现并分派独立调查，不能无证据等待或延长测试期限。阶段结论写入对应长期结果，不记录操作流水。
