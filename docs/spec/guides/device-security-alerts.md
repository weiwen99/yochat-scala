# 设备安全告警

<!-- tao:section scope -->
## 目标与边界

主界面的聊天列表上方显示本机保存的设备安全告警。每条记录包含完整用户公钥、设备公钥和当时观察到的原因，不用当前名单的别名替换历史设备身份。

告警说明已保存的历史观察，不替代当前授权判定，也不证明设备一定被盗；产品接线由
{need}`TASK_20261105_SHFGY5ZFTPM84P6Z`承接。当前权限及密钥处置见
[用户、密钥与设备](../engineering/keys-and-devices.md)，不要因历史告警自行恢复旧设备权限。

<!-- tao:section prerequisites -->
## 前提条件

本机身份已解锁，并已接收经过验证的设备名单。无需打开设置页面，也无需手动导入告警。

<!-- tao:section steps -->
## 操作步骤

查看主界面聊天列表上方的「设备安全告警」，核对完整用户公钥、设备公钥及以下原因：

- 本人其他设备出现在名单中，但观察到变更时尚未收到对应加入事件。
- 首次收到对端的完整名单时，当初交换的设备不在名单中。
- 观察名单变化时，某台设备已不在名单中。

“当初交换的设备”来自真实邀请或应答确认时保存的关系代次锚点，不由当前设备名单排序或后来发现的设备推测。同一代关系中的改名、发现提示更新、重复交换及先到的吊销均不改写这个锚点；新的关系代次另存自己的原交换设备。本人设备间同步携带这项明确的历史事实，但它不会使历史设备重新获得当前收发权限。

这些记录表示历史观察。后来的名单、别名或加入公告不会自动清除它们；核实异常时应通过其他渠道联系本人或对端。首次发布本机名单不作为本机的异常加入，对端正常首份名单也不作为本人设备加入告警。

<!-- tao:section troubleshooting -->
## 故障排查

读取失败时保留已经显示的记录并提示自动重试；锁定后记录从界面消失，重新解锁后从本机数据库读取。

记录与接受名单在同一 SQL 事务内保存。每条记录都要求已有实际用户及设备的历史绑定，同一用户、设备、原因只保留一条；原因只有上述三种，不保存名单版本、可变别名或任意公告内容。因此告警行数不超过历史绑定数的三倍，不随重放或改名次数增长。历史绑定本身是全局保留的设备事实，不按聊天会话独立收费；本项没有给它虚构一个对端计费归属，也没有增加总设备数上限。既有根名单证明缓存仍使用原有元数据额度。

查询每次最多返回 100 条，按持久游标继续读取，SQL 预算五秒。主界面每两秒尝试一次读取，已有请求未结束时不重复派发；前端五秒后结束本次等待，超时结果不再改变界面。锁定卸载主界面时清空该实例并拒绝迟到结果。重启后从保存的记录重新读取，不根据最新名单反推历史告警。此前未保存的瞬时观察无法可靠重建。
